# Card

{/* BEGIN: general */}

A rounded, clipped surface for grouping content: a restaurant tile, a food item, an order summary.

- **Import:** `import { Card } from '@droppy/design-system'`
- **Built on:** a plain `<div>` element.

<Canvas of={CardStories.Default} />

## Features

- Deliberately minimal: background, radius, and clipping only — no layout, image slot, or
  title slot. Callers compose those from their own markup and Droppy's other components.
- No resting shadow. A card that should lift adds it at the call site — for example
  `box-shadow: var(--ds-shadow-lift)` on hover, the treatment food-item tiles use.
- `padded` adds `--ds-space-sm` padding on all sides; unset, the shell is bare, since most of the
  components it replaces already own their internal padding.
- `interactive` adds a pointer cursor and a hover dim — the shell only. It wires no `onClick`;
  callers compose the click handling themselves.
- `overflow: hidden`, so an edge-to-edge image child clips to the card's own corner radius instead
  of squaring off past it.
- Merges any incoming `className` with its own `droppy-Card` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A tile or panel that groups related content and should read as a single surface — a grid
  item, a summary block, a preview card.

## When not to use

- An overlay that blocks or floats above the page — use [Modal](?path=/docs/overlays-modal--docs)
  for a blocking decision or [Sidebar](?path=/docs/overlays-sidebar--docs) for a panel reviewed
  alongside the page. `Card` has no portal, backdrop, or dismissal behavior.

{/* END: when-to-use */}

## How it works

### Padding

Bare by default, since most of the components this shell replaces already own their internal
padding. Pass `padded` for the ones that don't.

<Canvas of={CardStories.Padded} />

### Interactive

`interactive` adds a pointer cursor and dims the card to `opacity: 0.9` on hover — the same
treatment Mealdrop's restaurant and category cards used for their whole clickable surface.
`Card` doesn't attach the click handler itself; wrap it or spread `onClick` at the call site.

<Canvas of={CardStories.Interactive} />

### Clipping children to the radius

`overflow: hidden` means an edge-to-edge image child clips to the card's corner radius instead of
squaring off past it.

<Canvas of={CardStories.WithImage} />

## Keyboard & screen reader

`Card` renders a non-interactive `<div>` — there is no keyboard interaction to document, even with
`interactive` set, since that prop only changes appearance.

- **ARIA:** none — a plain container, unless the caller adds its own role or interactive element
  inside.
- **Screen reader:** not announced as a distinct region; its children are read in document order.
- **You must provide:** any interactive semantics (role, `tabIndex`, keyboard handling, accessible
  name) if the card as a whole is meant to be actionable — `interactive` only changes how it looks.

## Decision log

- **2026-07**: Card became the one shared shell (surface, radius, hover treatment) collapsing four per-component reimplementations — RestaurantCard, FoodItem, OrderSummary, and Category's round tile — with opt-in `interactive` and `padded` modifiers; corner rounding moved onto the shell so call sites deleted per-corner radius hacks, and Category's squared tile deliberately stays a plain figure with no card background ([migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-07**: card corners sit on the `--ds-radius-card` rung of the radius ladder — documented in the [Spacing and layout tokens](?path=/docs/design-tokens-spacing-and-layout--docs) as expressing "floatiness" — "the more elevated or overlay-like a surface, the larger the radius" — and card images take the card's radius on their touching corners only (8/8/0/0 over 0/0/8/8) so image and panel read as complementary halves of one shape.
- **2026-07**: card hover was unified as an opacity dim (two of Mealdrop's three card components already did this), reserving `--ds-shadow-lift` for the food-card hover pattern while resting cards stay flat, separated by background shifts rather than shadows — the [brand guidelines](?path=/docs/brand-guidelines--docs) codify this as "elevation means floating, not importance".
- **2026-08**: the brand motion rule "resting cards stay flat" was upheld rather than softened: the [brand guidelines](?path=/docs/brand-guidelines--docs) shipped with the contradiction stated out loud — the rule says flat, `Card.css` applied `--ds-shadow-lift` unconditionally — and a Mealdrop parity audit settled it by showing all three original consumers (FoodItem, RestaurantCard, round Category) were flat at rest, making the resting shadow the defect rather than the rule ([rule resolution](https://github.com/yannbf/droppy-ds/pull/4)). The resting shadow was removed in [droppy-ds #16](https://github.com/yannbf/droppy-ds/pull/16), closing [#10](https://github.com/yannbf/droppy-ds/issues/10).

## Known issues & open questions

- [#53](https://github.com/yannbf/droppy-ds/issues/53): no render/as escape hatch: a clickable card cannot render as &lt;a&gt; or &lt;button&gt;, and href is a type error. **Workaround:** wrap the card in a block-level &lt;a&gt;/router Link, or place a stretched absolutely-positioned link inside it.
- [#55](https://github.com/yannbf/droppy-ds/issues/55): `interactive` affordance is mouse-only: no :focus-visible ring or :active state, unlike every other clickable surface in the system. **Workaround:** add app CSS with a :focus-visible rule composing --ds-shadow-focus with --ds-shadow-lift, plus an :active rule for touch feedback.
- [#57](https://github.com/yannbf/droppy-ds/issues/57): background auto-flips to dark with OS preference, but Card sets no text color — inherited app text becomes illegible in apps that never opted into theming. **Workaround:** pin data-theme='light' on the root, adopt theming fully, or set color: var(--ds-color-text-primary) on the card / use DS text components inside it.
- [#59](https://github.com/yannbf/droppy-ds/issues/59): overflow:hidden silently truncates long unbroken text (no wrap/ellipsis) and clips edge-flush children's focus rings. **Workaround:** set overflow-wrap on your content nodes, keep focusable children inside padded regions, or override overflow at the cost of image corner clipping.
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only).
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
