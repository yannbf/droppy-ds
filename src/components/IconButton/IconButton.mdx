# IconButton

{/* BEGIN: general */}

A circular icon-only control for floating affordances — carousel arrows, overlay dismissals —
that stays legible over arbitrary imagery instead of following the page's theme.

```tsx
import { IconButton } from '@droppy/design-system'
```

<Canvas of={IconButtonStories.Default} />

## Features

- Keyboard activation and disabled semantics come from Base UI's `Button` under the hood — the
  same native-button contract `Button` gets.
- Deliberately not theme-reactive: it stays a light pill (white fill, dark icon) in dark mode,
  because it's built to sit on photography, not a themed surface.
- Only the radius and the focus ring are tokens — the fill, text colour, icon stroke, and drop
  shadow are fixed, by design.
- Two sizes, `4rem` default and `3rem` with `small`, with the icon scaled to match (`24` and
  `15`).
- The focus ring layers on top of the existing drop shadow instead of replacing it, so the
  button doesn't flatten when it gains focus.
- Merges any incoming `className` with its own classes.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A floating icon-only affordance that has to stay legible over arbitrary imagery — carousel
  arrows, overlay dismissals.
- A control that should look identical regardless of the surrounding theme.

## When not to use

- For an icon-only control that should follow the app's theme (for example, inline on a themed
  surface), use [Button](?path=/docs/actions-button--docs) with `round`, `clear`, and `icon`
  instead, because `IconButton` is deliberately theme-independent and won't flip in dark mode.
- For an action with visible text, use [Button](?path=/docs/actions-button--docs) instead,
  because `IconButton` has no children slot — it renders only the icon.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### It never goes dark

Deliberately not theme-reactive: it stays a light pill in dark mode so it reads against arbitrary
imagery. Only the radius and focus ring are tokens; the glyph resolves to `currentcolor`, which
inherits the button's own fixed `color` rather than the swappable icon token — so the icon stays
readable on the pill instead of flipping to the theme's colour underneath it.

## Do's and don'ts

### Do

- Always pass `aria-label`: `name` selects the icon only and contributes nothing to the button's
  accessible name
- Name the action rather than the glyph, e.g. "Next restaurants" rather than "chevron right"
- Use `small` inside dense chrome, and the default size where the control floats over imagery and
  needs a comfortable touch target

### Don't

- Don't pass children to an `IconButton`: they are silently discarded, and the control has no room
  for text
- Avoid `disabled` on a floating control users may hunt for: disabling removes it from the tab
  order and the accessibility tree

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

| Key   | Action                                           |
| ----- | ------------------------------------------------ |
| Enter | Activates the button (native behaviour)          |
| Space | Activates the button on keyup (native behaviour) |
| Tab   | Moves focus to/from the button, unless disabled  |

- **ARIA**: renders a real `<button>`, so there's no explicit role to manage.
- **Screen reader**: there is no visible text — the accessible name comes entirely from
  `aria-label`.
- **You must provide:** `aria-label` on every `IconButton` — `name` selects a visual icon only,
  it contributes nothing to the accessible name.
- **Known limitation:** disabling the control always removes it from the tab order and the
  accessibility tree — there's no `focusableWhenDisabled`-style escape hatch.

## Styling

- `--ds-radius-round` — border radius.
- `--ds-shadow-focus` — focus ring, layered with the existing drop shadow.
- The icon stroke resolves to `currentcolor`, inheriting the button's own `color` —
  `--ds-palette-neutral-800` — rather than `--ds-color-icon-default`, the token every other icon
  reads. That token flips per theme; this pill doesn't, so the glyph can't follow it.
- Everything else — background, text colour, drop shadow — is a fixed value, not a token, because
  `IconButton` is deliberately theme-independent.
- `className` merges with the component's own classes.

## Decision log

- **2025-03**: IconButton's `icon` prop was retyped from `string` to the `IconName` string-literal union alongside Icon and Button, making invalid names a compile-time error ([IconName union](https://github.com/yannbf/mealdrop/commit/14cf17a324a99c4744eec1495810f96d4e17bc5d)).
- **2026-07**: IconButton deliberately kept its theme-independent light-pill look — it sits on photography (carousel arrows over images), not on a themed surface, making it the one component in the set that does not respond to the theme — gaining only the DS focus ring and round-radius token in the migration ([buttons migration commit](https://github.com/yannbf/mealdrop/commit/c3c8adeb8e81c6e2c545b65728ed43a1aaf5d21e), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-08**: the glyph's colour moved from `--ds-color-icon-default` to `currentcolor`. [droppy-ds #289](https://github.com/yannbf/droppy-ds/pull/289) had dropped the glyph's hardcoded hex so it would read the shared icon token instead — but that token flips per theme and the pill it sits on never does, so the glyph went white-on-white in dark mode. Binding it to `currentcolor` keeps #289's goal (no unoverridable inline colour) while pinning the glyph to the pill's own fixed `color`.
- **Built on Base UI [`Button`](https://base-ui.com/react/components/button).** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#79](https://github.com/yannbf/droppy-ds/issues/79): onClick is typed () =&gt; void, rejecting handlers that use the MouseEvent delivered at runtime. **Workaround:** cast the handler (e.g. `as IconButtonProps['onClick']`) — the MouseEvent still arrives at runtime — or use the still-natively-typed onClickCapture/onMouseDown.
- [#82](https://github.com/yannbf/droppy-ds/issues/82): disabled, hover, and pressed states have no visual treatment — only rest and focus-visible are styled. **Workaround:** add app CSS on the shipped hooks, e.g. `.droppy-IconButton:disabled, .droppy-IconButton[data-disabled] { opacity: 0.4; cursor: default; }` plus a `:hover:not(:disabled)` rule.
- [#84](https://github.com/yannbf/droppy-ds/issues/84): aria-label is documented as mandatory but neither type-enforced nor warned about. **Workaround:** always pass `aria-label` (or `aria-labelledby`) at each call site, and enforce it via an app-level wrapper type or lint rule — the package will not catch the omission.
- [#86](https://github.com/yannbf/droppy-ds/issues/86): unknown name value throws a TypeError during render. **Workaround:** validate candidate names against the exported `iconNames` array before rendering, and wrap usage in an error boundary.
- [#88](https://github.com/yannbf/droppy-ds/issues/88): children are accepted by the type but silently discarded. **Workaround:** never pass children — use Button for controls with visible text (optionally wrap with a `children?: never` type in app code).
- [#90](https://github.com/yannbf/droppy-ds/issues/90): native button name attribute cannot be set — the name prop is repurposed for the icon. **Workaround:** carry the submitted pair in a hidden `<input name value>` (or handle it in onClick/onSubmit) instead of the button's own name/value.
- [#92](https://github.com/yannbf/droppy-ds/issues/92): docs: the disabled "known limitation" bullet is inaccurate on both claims. **Workaround:** no app change needed — reality is milder than documented, and `focusableWhenDisabled` does reach Base UI via a typed cast if needed.
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only).
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
- [#133](https://github.com/yannbf/droppy-ds/issues/133): the shared `--ds-shadow-focus` ring is below the 3:1 non-text contrast minimum in light theme.
