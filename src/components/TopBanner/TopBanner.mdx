# TopBanner

A full-width band at the top of a page, with a centered title over either a theme color or a
background photo — a category page's header, a restaurant's hero image.

- **Import:** `import { TopBanner } from '@droppy/design-system'`
- **Built on:** [Heading](?path=/docs/typography-heading--docs).

<Canvas of={TopBannerStories.Default} />

## Features

- Fixed 240px height, full width, centered content.
- Without `photoUrl`, the background is `--ds-color-surface-highlight`, the theme's accent
  surface color.
- With `photoUrl`, the band renders that image instead, covering the full band and centered —
  `photoUrl` takes any URL string, so it's the caller's job to host the image.
- `title` renders as a centered level-2 [Heading](?path=/docs/typography-heading--docs); its
  color switches to `--ds-color-text-on-inverse` when a photo is set, since the theme's regular
  text color doesn't reliably read over an arbitrary photo.
- Merges any incoming `className` with its own `droppy-TopBanner` class.
- Accepts an `onBackClick` prop for call-site parity with the Mealdrop component this replaces,
  but renders no back control of its own — see [Related](#related) for composing one.

## When to use

- The header band of a page that wants a large title over either a flat brand color or a hero
  photo — a category list, a restaurant detail page, a confirmation screen.

## When not to use

- A section title inline with the rest of the page's content — use
  [PageSection](?path=/docs/layout-structure-pagesection--docs) instead; `TopBanner` is a full-width
  band meant to sit above the page's content column, not inside it.

## How it works

### Theme color background

Without `photoUrl`, the band fills with the theme's accent surface color and the title uses the
regular primary text color.

<Canvas of={TopBannerStories.Default} />

### Photo background

`photoUrl` replaces the color with the given image, covering the band; the title switches to the
on-inverse text color so it stays legible over a photo.

<Canvas of={TopBannerStories.WithImage} />

## Keyboard & screen reader

`TopBanner` is a non-interactive layout element — there is no keyboard interaction to document.

- **ARIA:** none on the band itself; the title is a native `<h2>`, and the background photo, when
  set, is a CSS `background-image` rather than an `<img>`, so it carries no alt text and is never
  exposed to assistive technology as content.
- **Screen reader:** the title announces as a level-2 heading; the band itself is not announced
  as a distinct region.
- **You must provide:** a `title` whose meaning doesn't depend on the background photo — the
  photo is decorative as far as a screen reader is concerned.

## Styling

| Token                          | Used for                               |
| ------------------------------ | -------------------------------------- |
| `--ds-color-surface-highlight` | Background, when no `photoUrl` is set  |
| `--ds-color-text-primary`      | Title color, when no `photoUrl` is set |
| `--ds-color-text-on-inverse`   | Title color, when `photoUrl` is set    |

The 240px band height is a literal value — no token in the current scale matches it exactly.

`className` merges with the component's own `droppy-TopBanner` class.

## Decision log

- **2025-03**: an accessibility pass made the heading conditional — it renders only when a `title` is passed, instead of always emitting a possibly empty heading element — while keeping the optional `photoUrl` background with inverted (white) title text over photos; Droppy inherits this optional-title contract ([a11y fix](https://github.com/yannbf/mealdrop/commit/1c89bf7541a7b2b028338294fefe183dc70ac8e9), [adopted in migration](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747)).
- **2026-07**: the colour system placed top/promo banners among the handful of sites that use the green accent; per the [Color tokens](?path=/docs/design-tokens-colors--docs), green is a "surface accent — never ink", so the banner is a soft green surface carrying dark text while the neutral ramp does the rest of the UI.
- **2026-07**: `onBackClick` is accepted but deliberately unwired: Mealdrop's own back button is commented out in the source app, so the prop stays purely for call-site parity until either side puts the button back; otherwise the component was ported with props unchanged ([Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).

## Known issues & open questions

- [#254](https://github.com/yannbf/droppy-ds/issues/254): on-photo white title is driven by photoUrl truthiness, with no scrim — illegible over a missing, still-loading, or light photo. **Workaround:** preload the image and only pass photoUrl after onload succeeds, and/or add an app-CSS scrim (::before overlay on the band, which is already position: relative) or text-shadow so the white title stays readable.
- [#255](https://github.com/yannbf/droppy-ds/issues/255): long titles break the documented centered layout: wrapped lines left-align, unbroken strings overflow the band, tall wraps spill past the fixed 240px height. **Workaround:** add app CSS (text-align: center and overflow-wrap: anywhere on the heading, padding-inline and overflow: hidden on the band), or truncate titles before passing them.
- [#256](https://github.com/yannbf/droppy-ds/issues/256): accepts no children — the docs' pointer to "composing" a back control leads nowhere, and JSX children are silently dropped in non-TS apps. **Workaround:** wrap TopBanner in your own position: relative container and absolutely position the back control (or other content) over the band instead of passing children.
- [#257](https://github.com/yannbf/droppy-ds/issues/257): dark theme: the no-photo band is nearly invisible — surface-highlight collapses to #2c2c2c on a #202020 page. **Workaround:** override the band's dark-theme background in app CSS (e.g. surface-sunken plus a subtle border, mirrored in the prefers-color-scheme fallback), or always pass a photoUrl.
- [#258](https://github.com/yannbf/droppy-ds/issues/258): onBackClick is accepted by the type but never invoked — dead prop. **Workaround:** don't pass onBackClick; render your own back control absolutely positioned over the band inside a position: relative wrapper.
- [#259](https://github.com/yannbf/droppy-ds/issues/259): photoUrl is interpolated into url("...") unescaped — a double quote silently disables the background image. **Workaround:** encode the URL before passing it (encodeURIComponent for data-URI payloads, encodeURI or new URL().toString() for http(s) URLs).
- [#260](https://github.com/yannbf/droppy-ds/issues/260): heading level hard-coded to h2 — a hero banner cannot be the page's h1. **Workaround:** keep the page's real h1 elsewhere (optionally visually hidden) with the same title; there is no prop-level fix.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
