# Sidebar

{/* BEGIN: general */}

A panel that slides in from the trailing edge, for content reviewed alongside the page rather than instead of it.

```tsx
import { Sidebar } from '@droppy/design-system'
```

{/* Open overlay stories portal to document.body; an iframe keeps them inside the canvas. */}

<Canvas of={SidebarStories.Default} story={{ inline: false, height: '480px' }} />

## Features

- **Focus trap** — Tab loops inside the panel while it's open, so keyboard users can't tab into the page behind it.
- **Scroll lock** — the page behind the sidebar stops scrolling while it's open.
- **Escape, outside-press, and swipe-to-dismiss** — closing works from the keyboard, a click outside the panel, or a swipe toward the trailing edge on touch.
- **Full-width on mobile** — below 768px the panel takes the full viewport width instead of a fixed 420px.
- **Pinned footer slot** — an optional `footer` sits fixed to the bottom of the panel while the content above it scrolls independently.
- **Portal by default** — content renders at the end of `document.body`, so a parent's `overflow: hidden` or `z-index` stacking context can't clip or bury it.
- **ARIA dialog wiring** — `role="dialog"` and the accessible name (from `title`) are set for you.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- Content the person reviews _alongside_ the page rather than instead of it — a cart is the shape the `Open` story demonstrates: line items stay visible while the page underneath is still there to return to.
- A running total or a set of filters the person may check, adjust, and dismiss without the flow being interrupted by a forced decision.
- Content that benefits from a pinned action at the bottom while the rest scrolls — the `WithFooter` story's total-and-checkout pattern.

## When not to use

- To ask for a single decision that should block the rest of the page until it's made — a confirmation, an "are you sure" — use [Modal](?path=/docs/overlays-modal--docs). Sidebar shares the page; Modal takes it over.
- To explain what a control does before it's activated, use [Tooltip](?path=/docs/overlays-tooltip--docs) — a hint doesn't need a panel or a focus trap.

## Do's and don'ts

### Do

- Write a `title` that describes the panel's contents, e.g. "Your order" rather than "Details": it
  is the only accessible name the panel gets
- Put totals and the primary action in `footer`, so they stay pinned while the contents scroll
- Keep the page behind the panel meaningful; users open a sidebar to work with the page, not to
  leave it

### Don't

- Don't make swipe-to-dismiss the only way out of a flow: it is pointer-only, and keyboard users
  have Escape and the close button
- Avoid a panel whose contents change what the page underneath means; users expect the page they
  left to be the page they come back to

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

| Key                 | Action                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Tab` / `Shift+Tab` | Moves focus through the panel's tabbable elements; loops back to the start rather than escaping to the page |
| `Escape`            | Closes the panel                                                                                            |

- **ARIA**: the popup carries `role="dialog"`; the accessible name is wired automatically from the `title` prop.
- **Screen reader**: on open, the dialog is announced by its title; on close, focus returns to wherever it was before the panel opened.
- **Gesture honesty**: swipe-to-dismiss is pointer-only and has no keyboard equivalent — keyboard and screen reader users rely on Escape and the visible close button, both always present regardless of touch support.
- **You must provide:** a `title` that actually describes the panel's contents ("Your order" rather than something generic) — it is the only accessible name the dialog gets.

## Styling

- `--droppy-sidebar-topbar-height` — the top bar's height (default `4.5rem`), subtracted from the viewport when the content area computes its own scroll bound.
- `--droppy-sidebar-footer-height` — the footer's height (default `165px`), subtracted the same way. Override both together if you resize either slot, so the content area's scroll maths stays correct.
- `className` — merged with the panel's own classes, so wrapping `Sidebar` in `styled()` or adding utility classes composes rather than replacing the built-in styling.

The panel's desktop width (420px) is fixed by the design system and isn't exposed as a custom property; use `className` for one-off width changes.

## Decision log

- **2020-10**: overlays must lock body scroll while open — established as an early Mealdrop fix long before the design system existed, later delegated to Base UI's built-in scroll lock when Sidebar moved to Drawer ([mealdrop #2](https://github.com/yannbf/mealdrop/pull/2), [scroll-lock commit](https://github.com/yannbf/mealdrop/commit/c4aef0406a2e1cfddb072c9718d9f64f3c1fefdf)).
- **2026-07**: Sidebar was reimplemented on Base UI Drawer (swipeDirection right), replacing the CSSTransition slide, Escape hook, and scroll lock while preserving test ids verbatim; Drawer.Title renders the existing Heading so the drawer has a real accessible name, which forced Heading to forward ref and rest props ([sidebar commit](https://github.com/yannbf/mealdrop/commit/6d946fcf90684f3d87b79d6d081fbf29d41f26ce), [heading commit](https://github.com/yannbf/mealdrop/commit/40f20f7aba828e146634d88e58cbb324541645c4), [migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747)).
- **2026-07**: Drawer.Portal's document.body default pushed the drawer outside the story canvas and forced tests to query the document body; rather than keep rewritten story queries (an earlier workaround, reversed), the drawer portals into the same in-app `#modal` container Modal uses, falling back to body, keeping interaction stories byte-identical to their pre-migration versions ([portal-target commit](https://github.com/yannbf/mealdrop/commit/798e2fad44b666c3f4165b3b447a2b636a0b8a07), [earlier query-scope commit](https://github.com/yannbf/mealdrop/commit/5b449fe827cfbf9238a59c0d6b5a0efc24604ce4)).
- **2026-07**: Sidebar took a `container` prop accepting an element or CSS selector (default document.body) because Mealdrop portalled into a `#modal` node hard-coded in its own index.html and a package cannot assume that node exists; selector resolution happens in an effect, safe because an overlay is closed on first paint ([Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md), [useContainer.ts](https://github.com/yannbf/droppy-ds/blob/main/src/utils/useContainer.ts)).
- **2026-07**: the pixel-parity pass separated theme opinion from behaviour: the Drawer backdrop was darkened from the theme's 20% black scrim to the original 40%, and the 300ms slide reverted to default ease over the theme's slower easing — establishing motion tokens as brand voice a consumer may legitimately retime ([scrim parity commit](https://github.com/yannbf/mealdrop/commit/e085f7d327906cc5568613e3fab91e343cd5ef6f), [animation timing commit](https://github.com/yannbf/mealdrop/commit/ac151a9710b9eb297274485d7bfa571f7acf19aa)).
- **Built on Base UI [`Drawer`](https://base-ui.com/react/components/drawer).** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#137](https://github.com/yannbf/droppy-ds/issues/137): tooltips (and other popups) opened inside the panel are painted behind it. **Workaround:** raise the tooltip layer or lower the sidebar's z-index from app CSS (e.g. `.droppy-Sidebar-viewport { z-index: 30 } .droppy-Sidebar-backdrop { z-index: 29 }`).
- [#140](https://github.com/yannbf/droppy-ds/issues/140): content area always reserves 165px for the footer, even when no `footer` is passed. **Workaround:** pass a `className` that sets `--droppy-sidebar-footer-height: 0px` when rendering without a footer.
- [#144](https://github.com/yannbf/droppy-ds/issues/144): A `container` selector is resolved once and silently falls back to `document.body` when it does not match. **Workaround:** pass a resolved `HTMLElement` (held in state) instead of a selector string.
- [#148](https://github.com/yannbf/droppy-ds/issues/148): an empty or malformed `container` selector throws a DOMException from an effect. **Workaround:** resolve the selector yourself inside try/catch and pass the resulting element (or `null`) instead of the string.
- [#151](https://github.com/yannbf/droppy-ds/issues/151): slide-in/out and backdrop fade are not reduced under `prefers-reduced-motion: reduce`. **Workaround:** add `@media (prefers-reduced-motion: reduce) { .droppy-Sidebar, .droppy-Sidebar-backdrop { transition: none } }` in app CSS.
- [#155](https://github.com/yannbf/droppy-ds/issues/155): close button's accessible name is hardcoded to the English string "close sidebar". **Workaround:** hide the built-in button via its internal test id and supply your own close control.
- [#157](https://github.com/yannbf/droppy-ds/issues/157): the scrollable content region is not keyboard focusable, so overflowing non-interactive content cannot be scrolled by keyboard in Safari. **Workaround:** wrap children in your own element with `tabIndex={0}`, `role="region"` and an `aria-label`.
- [#309](https://github.com/yannbf/droppy-ds/issues/309): the content region reserves the topbar and footer heights without their padding, so long content scrolls behind the pinned footer and its last rows cannot be reached. **Workaround** (partial): raise `--droppy-sidebar-topbar-height` and `--droppy-sidebar-footer-height` in app CSS to the parts' rendered heights; the `100vh` assumption still breaks inside a container shorter than the viewport.
- [#160](https://github.com/yannbf/droppy-ds/issues/160): backdrop dim is 60% in dark mode instead of the declared 40%, and single-class overrides of the backdrop fail there. **Workaround:** match the theme's specificity in the override (`html[data-theme='dark'] .droppy-Sidebar-backdrop { … }`) or import the DS stylesheet into a cascade layer.
- [#164](https://github.com/yannbf/droppy-ds/issues/164): mouse and pen drags inside the panel dismiss it, although the docs describe swipe-to-dismiss as touch-only. **Workaround:** mark drag-sensitive content with Base UI's `data-base-ui-swipe-ignore` attribute; the gesture cannot be disabled through a Sidebar prop.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
