# Accordion

{/* BEGIN: general */}

A stack of collapsible sections, each labelled by a header — an FAQ list, a set of grouped
filters, a details panel with several independent parts.

```tsx
import { Accordion } from '@droppy/design-system'
```

<Canvas of={AccordionStories.Default} />

## Features

- **`items` covers the common case**: an array of `{ value?, title, content, disabled? }` renders
  the whole list — no need to compose `Accordion.Item`/`Header`/`Trigger`/`Panel` by hand. `value`
  falls back to the item's index when omitted.
- **Single-open by default**: opening one item closes whichever was open before. Pass
  `openMultiple` to allow several panels open at once.
- **`value`/`defaultValue`/`onValueChange` passthrough**, for a controlled accordion driven by
  state outside the component.
- **Animated panel height**, driven by Base UI's own measurement — no fixed heights or JS
  transitions to maintain.
- **Renders the theme's plus icon inside each trigger**, which rotates 45° into a cross when its
  panel opens.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A list of independent sections where showing everything at once would be overwhelming — an FAQ,
  a filter panel with several groups, a settings page split into topics.

## When not to use

- For content that should always be visible together, don't collapse it — an accordion trades
  scannability for compactness, and hiding content the user needs constantly just adds clicks.
- For a single show/hide toggle rather than a list of sections, use Base UI's `Collapsible`
  directly instead — `Accordion` is built for managing several sections' open state together.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### Single-open replaces

By default, opening an item closes whichever one was open — only one panel is visible at a time,
so the list never grows past one panel's worth of height. `openMultiple` opts out of that.

<Canvas of={AccordionStories.SingleOpenReplaces} />

### Controlled vs. uncontrolled

Left alone, the accordion owns its open state, and `defaultValue` seeds it. Passing `value` hands
that ownership to the caller — but only together with `onValueChange`, since the component then
stops updating itself. One without the other leaves the accordion stuck.

<Canvas of={AccordionStories.ControlledValue} />

### Rich titles and content

`title` and `content` take any `ReactNode`, so a header can carry a badge and a panel can hold
markup rather than a string.

<Canvas of={AccordionStories.RichContent} />

### Open/close animation

Base UI measures each panel and writes its height to `--accordion-panel-height`; the theme
transitions `height` on top of that variable, and rotates the trigger's plus icon 45° into a cross
while `[data-panel-open]` is set. Nothing here needs a fixed height.

<Canvas of={AccordionStories.PanelHeightTransition} />

## Anatomy

`Accordion` renders seven parts, each carrying a `data-part` attribute. Open the story below in
the canvas and use the **Anatomy** panel to hover a part and see it highlighted, or hover the
canvas to activate the matching entry.

<Canvas of={AccordionStories.Anatomy} />

| Part    | `data-part` | Renders    | Purpose                                                                    |
| :------ | :---------- | :--------- | :------------------------------------------------------------------------- |
| Root    | `root`      | `<div>`    | Owns the shared open state, the border, and the column layout              |
| Item    | `item`      | `<div>`    | One collapsible section; carries `[data-panel-open]` while open            |
| Header  | `header`    | `<h3>`     | Puts each trigger in the page outline                                      |
| Trigger | `trigger`   | `<button>` | Toggles its panel; carries `aria-expanded`                                 |
| Icon    | `icon`      | `<svg>`    | The plus glyph, rotated 45° into a cross while open                        |
| Panel   | `panel`     | `<div>`    | The animated region; mounted only while open, sized by the height variable |
| Content | `content`   | `<div>`    | The padded inner wrapper the panel clips as it animates                    |

The tree is flat by design: `items` renders the whole list, so there is no sub-component to
compose. Item order is the array's order.

## Keyboard & screen reader

| Key / interaction | Context         | Action                                                          |
| ----------------- | --------------- | --------------------------------------------------------------- |
| Tab / Shift+Tab   | any             | Moves focus between triggers, in document order                 |
| Enter / Space     | focused trigger | Toggles that item's panel open or closed                        |
| Arrow keys        | any             | No effect — Accordion does not use roving focus between headers |

<Canvas of={AccordionStories.TestKeyboardTabFlow} />

- **ARIA:** each trigger is a `<button>` with `aria-expanded`, inside an `<h3>` header; each panel
  carries `role="region"` linked to its trigger via `aria-labelledby`.
- **Screen reader:** announces each header as a heading, and each trigger's expanded/collapsed
  state; panel content is announced as a landmark region once open.
- **You must provide:** a meaningful `title` per item — it becomes both the visible label and the
  trigger's accessible name.

## Styling

Droppy's own stylesheet carries no rules for `Accordion` — the theme layer's `AccordionRoot`,
`AccordionItem`, `AccordionHeader`, `AccordionTrigger`, `AccordionIcon`, `AccordionPanel`, and
`AccordionContent` classes cover the border, spacing, icon rotation, and panel-height animation in
full.

`className` merges onto the root, so it composes with the theme layer rather than replacing it.

## API reference

<ArgTypes of={AccordionStories} />

### `items`

The only required prop. Each entry is `{ value?, title, content, disabled? }`, and the array's
order is the render order.

<Canvas of={AccordionStories.Items} />

### Item `value`

Identifies an item in `value`/`defaultValue`/`onValueChange`. Omitted, it falls back to the item's
index — fine for a static list, but give items explicit values if the list can reorder.

<Canvas of={AccordionStories.ItemValues} />

### Item `title` and `content`

Both are `ReactNode`. See [Rich titles and content](#rich-titles-and-content) above.

### Item `disabled`

Keeps the trigger focusable but stops it toggling, by click or keyboard. Sibling items are
unaffected.

<Canvas of={AccordionStories.DisabledItem} />

### `openMultiple`

Allows more than one panel open at once.

<Canvas of={AccordionStories.OpenMultiple} />

### `defaultValue`

The item values open on first render, for an uncontrolled accordion.

<Canvas of={AccordionStories.DefaultValue} />

### `value` and `onValueChange`

The controlled pairing. See [Controlled vs. uncontrolled](#controlled-vs-uncontrolled) above.

### `className`

Merged onto the root alongside the theme's classes.

## Decision log

- **2026-07**: Droppy's Accordion took a data-driven `items: {value, title, content}[]` array instead of exposing the underlying compound-component composition, keeping call sites declarative; item values fall back to the item's index ([additional components commit](https://github.com/yannbf/droppy-ds/commit/1fba4ce05fa71da8aa51a56ea60dae6b218c1868)).
- **Built on Base UI [`Accordion`](https://base-ui.com/react/components/accordion).** The
  expand/collapse behaviour, the panel measurement, and the ARIA wiring come from there; Droppy
  supplies the `items` shape, the theme classes, and the plus icon.

## Known issues & open questions

- [#30](https://github.com/yannbf/droppy-ds/issues/30): theme caps the root at max-width 20rem (320px); undocumented and not liftable via any prop. **Workaround:** pass a className and set max-width: none in app CSS loaded after the DS stylesheet.
- [#32](https://github.com/yannbf/droppy-ds/issues/32): closed panels unmount their content, destroying all descendant state; keepMounted/hiddenUntilFound are not exposed. **Workaround:** lift content state out of the panel (or use openMultiple to reduce churn); panels cannot be kept mounted through this wrapper.
- [#35](https://github.com/yannbf/droppy-ds/issues/35): index-fallback item values bind open state and React keys to list position; dynamic lists shift open panels and values can collide. **Workaround:** always pass explicit stable string values per item; avoid mixing the index fallback with stringified-integer explicit values.
- [#38](https://github.com/yannbf/droppy-ds/issues/38): controlled `value` becoming undefined after mount throws a TypeError on the next trigger click; starting undefined locks the accordion uncontrolled. **Workaround:** always pass an array once controlled ([] for all closed), never undefined; reset uncontrolled accordions by remounting with a new key.
- [#40](https://github.com/yannbf/droppy-ds/issues/40): heading level is hardcoded to &lt;h3&gt; with no way to fit it to the page outline. **Workaround** (structural only): arrange surrounding headings so h3 fits the outline; the level itself cannot be changed.
- [#111](https://github.com/yannbf/droppy-ds/issues/111): onValueChange is typed with one parameter, hiding Base UI's runtime eventDetails argument and its cancel() veto. **Workaround:** cast the handler in TS (or just declare the second param in JS); the runtime forwards eventDetails unchanged.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
- [#133](https://github.com/yannbf/droppy-ds/issues/133): the shared `--ds-shadow-focus` ring is below the 3:1 non-text contrast minimum in light theme.
- [#138](https://github.com/yannbf/droppy-ds/issues/138): theme chrome is bound to unnamespaced global classes (`.Button`, `.Input`, `.FieldRoot`, …) with no cascade layer, so host-app CSS collides in both directions.

## Related

- For a single independent show/hide section rather than a managed list, reach for Base UI's
