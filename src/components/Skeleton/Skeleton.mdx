# Skeleton

{/* BEGIN: general */}

A loading placeholder that stands in for content before it arrives, shaped to match what it will
become.

```tsx
import { Skeleton } from '@droppy/design-system'
```

<Canvas of={SkeletonStories.Default} />

## Features

- Renders inline-block by default, so a bare `<Skeleton />` sits inside a `Heading` or a line of
  text and takes on the surrounding font size.
- `width` and `height` default to `100%` and `1em` — a single line that fills its container at
  text height — and accept either a number (treated as pixels) or a CSS length string.
- `style` passes through and wins over the component's own inline styles, so a caller can set a
  border radius or margin that matches the shape it's covering.
- Shimmers with a CSS gradient animation between the theme's skeleton tokens, and turns static
  under `prefers-reduced-motion: reduce` rather than disabling the sweep with JavaScript.
- `aria-hidden="true"` always — a placeholder announces nothing on its own.
- Merges any incoming `className` with its own `droppy-Skeleton` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- In place of text, an image, or any block of content while it loads, sized to match the shape
  that content will take.
- Composed into an existing layout — a card, a list row, a form — so the page's structure doesn't
  shift once the real content arrives.

## When not to use

- For a full-page loading wait with no layout to preview yet — a shape-matching placeholder needs
  a shape to match.
- For content whose final size isn't known. A skeleton that guesses wrong shifts the layout the
  moment real content replaces it, which is the exact jump skeletons exist to prevent.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### Composing a block of placeholders

Several `Skeleton`s at different widths stand in for a heading and a few lines of body text. Each
one only carries the loading state visually — the surrounding container is what should announce
that the region is busy, which is why the placeholders sit `aria-hidden` beneath one
`role="status"`.

<Canvas of={SkeletonStories.TextBlock} />

### The shimmer

The sweep animates `background-position` across a gradient built from `--ds-color-skeleton-base`
and `--ds-color-skeleton-highlight`, so it already matches the theme and flips with it
automatically. Under `prefers-reduced-motion: reduce` the animation is removed outright and the
background falls back to the flat base token — a placeholder still reads as a placeholder when it
holds still.

## Anatomy

`Skeleton` is a single-part component: one `<span>`, so it can sit inline inside a `Heading` or a line of text and take on the surrounding font size. It has no children and announces nothing.

## Do's and don'ts

### Do

- Use `Skeleton` while loading content whose shape you already know, so the layout doesn't jump
  when the real content arrives.
- Add loading semantics on the surrounding container (`role="status"` with a label) — `Skeleton`
  itself is silent to assistive tech.

### Don't

- Avoid `Skeleton` when the final content's size is unknown — a wrong guess causes the exact
  layout jump it exists to prevent; use
  [Spinner](?path=/docs/feedback-status-spinner--docs) instead.

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

`Skeleton` is non-interactive and carries no role — there is no keyboard interaction to document.

- **ARIA:** `aria-hidden="true"` on the root element, always.
- **Screen reader:** not announced — the placeholder contributes nothing to the accessibility
  tree.
- **You must provide:** the loading semantics on the container that holds the skeletons — for
  example `role="status"` with an `aria-label`, or `aria-busy="true"` — since `Skeleton` itself
  announces nothing.

## Decision log

- **2026-07**: Skeleton shipped as a dependency-free CSS shimmer reading skeleton tokens directly, replacing the react-loading-skeleton dependency and Mealdrop's `<SkeletonTheme>` provider (which needed an @ts-expect-error for wrong types and manual base/highlight colours per theme); the per-instance `width`/`height` sizing API was kept so loading layouts port over line-for-line ([migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-08**: a visual-parity audit traced the shimmer's choppy double pulse to keyframes travelling two tile periods per cycle over a 200%-wide gradient, and proposed 100%/−100% stops for one evenly-eased sweep per 1.6s cycle. The PR was closed unmerged, so the defect is tracked as [#11](https://github.com/yannbf/droppy-ds/issues/11) ([droppy-ds #8](https://github.com/yannbf/droppy-ds/pull/8)).
- **2026-08**: `.droppy-Skeleton` now sets `background-color: var(--ds-color-skeleton-base)` under the shimmer gradient and declares `background-repeat: repeat` explicitly, instead of relying on the gradient alone and the browser's default repeat behaviour — a consumer `background-repeat: no-repeat` reset had been enough to make the placeholder flash transparent every cycle ([droppy-ds #289](https://github.com/yannbf/droppy-ds/pull/289), closing [#264](https://github.com/yannbf/droppy-ds/issues/264)).
- **Built on a plain `<span>`.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#168](https://github.com/yannbf/droppy-ds/issues/168): no prop forwarding: data-\* and aria-\* attributes type-check but are silently dropped. **Workaround:** put ids, test ids, handlers and refs on a wrapper element you own, and select the placeholder in tests via the stable `.droppy-Skeleton` class.
- [#171](https://github.com/yannbf/droppy-ds/issues/171): width/height are always emitted as inline styles, so className-based sizing has no effect. **Workaround:** size skeletons with the `width`/`height` props or the `style` prop, or mark stylesheet sizing `!important`.
- [#11](https://github.com/yannbf/droppy-ds/issues/11): skeleton shimmer completes two uneven passes per cycle. **Workaround:** redeclare the shimmer keyframes with 100%/−100% stops in app CSS.
- [#174](https://github.com/yannbf/droppy-ds/issues/174): unitless numeric strings and non-finite numbers silently fall back to the default size. **Workaround:** normalize dimensions at the call site — pass finite numbers guarded with `Number.isFinite`, or strings that carry a unit.
- [#176](https://github.com/yannbf/droppy-ds/issues/176): docs list aria-busy="true" as an alternative to role="status", but it announces nothing. **Workaround:** ignore the `aria-busy` option and use the docs' `role="status"` + `aria-label` container pattern, as the TextBlock story does.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
