# Select

{/* BEGIN: anatomy */}

## Anatomy

A label above a wrapper that positions the chevron over the native control. There is no listbox part: the options are real `<option>` elements the platform renders.

<Canvas of={SelectStories.Anatomy} />

| Part    | `data-part` | Renders    | Purpose                                |
| :------ | :---------- | :--------- | :------------------------------------- |
| Root    | `root`      | `<div>`    | The field: label above, control below  |
| Label   | `label`     | `<label>`  | Tied to the control by `for`/`id`      |
| Wrapper | `wrapper`   | `<div>`    | Positions the chevron over the control |
| Control | `control`   | `<select>` | The native control                     |

## Decision log

- **2026-07**: Select intentionally stayed a native `<select>` instead of adopting Base UI's scripted listbox: react-hook-form registers it uncontrolled and the platform picker beats any custom listbox for accessibility and muscle memory on touch devices — only the styling moved onto DS tokens ([forms commit](https://github.com/yannbf/mealdrop/commit/0b4027271b30a4e31360eadaf41f5e1ea46a5f55), [Select.tsx](https://github.com/yannbf/droppy-ds/blob/main/src/components/Select/Select.tsx)).
- **2026-07**: onChange now coerces numeric options to numbers but returns strings for non-numeric ones — fixing Mealdrop's behaviour of running every value through `Number()`, which turned text options into NaN ([Select.tsx](https://github.com/yannbf/droppy-ds/blob/main/src/components/Select/Select.tsx), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md), [migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747)).
- **2026-07**: the chevron changed from a data-URL SVG with a baked-in colour (string-replaced per theme via a JavaScript lookup) to a CSS mask over a token-coloured layer that flips themes in pure CSS, and the label moved before the control in the DOM so reading order matches visual order — Mealdrop had it after only so a sibling selector could drive the focus highlight, which `:has()` handles now ([Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-07**: because Droppy's spacing scale is offset one step from Mealdrop's original tokens (`--ds-space-xs` is 1rem, not 0.5rem), spacing must be migrated by value rather than by token name: Select's field padding was remapped to the nearest DS step (`--ds-space-sm` for a 1.25rem original with no exact match) and its label gap to the exact `--ds-space-2xs` ([select spacing commit](https://github.com/yannbf/mealdrop/commit/05231ffb1b8a1a7475f148dbfdbba448daef701d)).
- **2026-08**: the chevron and its reserved clearance moved from fixed `rem` sizes to `em`, and `.droppy-Select-control` now sets `font-size: inherit`, so both scale with the control's font-size instead of staying pinned to a size that dwarfed compact controls ([droppy-ds #289](https://github.com/yannbf/droppy-ds/pull/289), [droppy-ds #290](https://github.com/yannbf/droppy-ds/pull/290), closing [#265](https://github.com/yannbf/droppy-ds/issues/265)).
- **Built on the native `<select>` element — not a Base UI primitive. On touch devices a native select opens the platform's own picker, which no scripted listbox matches for accessibility or muscle memory; Droppy restyles the control and supplies its own chevron on top.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#146](https://github.com/yannbf/droppy-ds/issues/146): always controlled: with no value/onChange state loop the control renders blank and reverts every pick, and defaultValue is ignored. **Workaround:** always drive it from state — hold the value in the consumer and pass both `value` and `onChange`; never pass `defaultValue`.
- [#152](https://github.com/yannbf/droppy-ds/issues/152): onChange rewrites numeric-looking option strings ("01" → 1), so the returned value no longer matches any option and the control blanks. **Workaround:** pass numeric options as real numbers and keep string options canonical (`String(Number(s)) === s`), or read the raw string from an `onInput` handler passed through rest props.
- [#156](https://github.com/yannbf/droppy-ds/issues/156): the control has no `font-family` token applied, so its typeface falls back to the browser's UA default rather than matching the label above it — `font-size` now inherits from the ambient context (`font-size: inherit`), so only the family is still unset. **Workaround:** app CSS `.droppy-Select-control { font-family: var(--ds-type-family-body); }`.
- [#161](https://github.com/yannbf/droppy-ds/issues/161): A disabled Select is visually indistinguishable from an enabled one. **Workaround:** app CSS for `.droppy-Select-control:disabled` plus `:has()` rules for the label and chevron.
- [#165](https://github.com/yannbf/droppy-ds/issues/165): in dark mode the native option list opens with the light UA palette — the stylesheet never declares color-scheme. **Workaround:** declare `color-scheme` in app CSS alongside the `data-theme` switch, or pass `style={{ colorScheme: 'dark' }}` (style reaches the inner select).
- [#169](https://github.com/yannbf/droppy-ds/issues/169): children are silently discarded — &lt;option&gt; markup, &lt;optgroup&gt;, and label-different-from-value are not possible. **Workaround** (plain lists only): use the `options` prop; none within this component when option text must differ from the submitted value, or for optgroups/disabled options.
- [#173](https://github.com/yannbf/droppy-ds/issues/173): A long option string makes the control overflow its container — the flex item has no min-width: 0. **Workaround:** app CSS `.droppy-Select-control { min-width: 0; }`.
- [#177](https://github.com/yannbf/droppy-ds/issues/177): className styles the wrapper while style and every other prop land on the &lt;select&gt;, so the style prop cannot size the control and no prop targets it. **Workaround:** size the field with `className` on the wrapper and reach the control with a descendant selector (`.myClass .droppy-Select-control`).
- [#310](https://github.com/yannbf/droppy-ds/issues/310): `label` is typed optional, but omitting it leaves the control with no accessible name. **Workaround:** pass `label` at every call site.
- [#181](https://github.com/yannbf/droppy-ds/issues/181): id="" defeats the generated-id fallback and leaves the label associated with nothing. **Workaround:** never pass an empty-string id — use `id={maybeId || undefined}` or omit the prop.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
