# Separator

{/* BEGIN: anatomy */}

## Anatomy

`Separator` is a single-part component: one `<div>` with `role="separator"` and no children. The caller sizes it — width or height in CSS — to read visually as a line.

<Canvas of={SeparatorStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                                              |
| :--- | :---------- | :------ | :----------------------------------------------------------------------------------- |
| Root | `root`      | `<div>` | The divider, carrying `role="separator"`, `aria-orientation`, and `data-orientation` |

{/* END: anatomy */}

## Known issues & open questions

- [#127](https://github.com/yannbf/droppy-ds/issues/127): vertical orientation is fixed at 1.25rem tall and never stretches to its container. **Workaround:** the vertical size lives on the unqualified `.SeparatorRoot` rule, so `style={{ height: 'auto', alignSelf: 'stretch' }}` or an app class loaded after the DS stylesheet overrides it.
- [#131](https://github.com/yannbf/droppy-ds/issues/131): `ref` is part of the public prop type but is never attached on React 18. **Workaround:** on React 18, wrap the Separator in your own element and read `wrapper.firstElementChild`, or query the always-present `.droppy-Separator` class; on React 19 `ref` works as typed.
- [#134](https://github.com/yannbf/droppy-ds/issues/134): `className` overrides of a horizontal separator's size are outranked by the theme's attribute selector. **Workaround:** match the theme's specificity with `.your-class[data-orientation='horizontal']`, or use the `style` prop.
- [#139](https://github.com/yannbf/droppy-ds/issues/139): docs say margin comes from the theme's `SeparatorRoot` class, but no margin is defined anywhere. **Workaround:** supply spacing yourself via a `gap` on the parent container or a margin on the Separator — the theme sets no margin, so there is no specificity conflict.
- [#143](https://github.com/yannbf/droppy-ds/issues/143): every instance is exposed as `role="separator"`, including the decorative uses the docs recommend, and the opt-out is undocumented. **Workaround:** pass `role="presentation"` (optionally with `aria-orientation={undefined}`) or `aria-hidden`, which pass through `...rest` and override Base UI's internal props.
- [#147](https://github.com/yannbf/droppy-ds/issues/147): `children` type-checks and renders text inside the 1px-tall rule. **Workaround:** don't pass children — compose a labelled divider in app code as a flex row with two Separators around the label.
- [#150](https://github.com/yannbf/droppy-ds/issues/150): `render` is removed from the prop type but still honoured at runtime, leaving no supported way to change the element. **Workaround:** render your own `<hr>`/`<li>` and apply the global theme classes to it, rather than relying on the untyped `render` passthrough.
- [#154](https://github.com/yannbf/droppy-ds/issues/154): A function `className` (valid on the underlying Base UI part) is stringified into the class attribute. **Workaround:** always pass a plain string — the only state is `orientation`, which the caller already controls.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
- [#138](https://github.com/yannbf/droppy-ds/issues/138): theme chrome is bound to unnamespaced global classes (`.Button`, `.Input`, `.FieldRoot`, …) with no cascade layer, so host-app CSS collides in both directions.
