# FooterCard

{/* BEGIN: anatomy */}

## Anatomy

A heading above a list of links. The list disappears entirely when `links` is empty, so a column of `children` alone renders no stray `<ul>`.

<Canvas of={FooterCardStories.Anatomy} />

| Part  | `data-part` | Renders                         | Purpose                                            |
| :---- | :---------- | :------------------------------ | :------------------------------------------------- |
| Root  | `root`      | `<div>`                         | The column: heading above, list and children below |
| Title | `title`     | `<h2>`                          | The column heading                                 |
| List  | `list`      | `<ul>`                          | Absent when `links` is empty                       |
| Item  | `item`      | `<li>`                          | One per entry                                      |
| Link  | `link`      | `<a>` (or the `render` element) | Rendered through `Link`                            |

{/* END: anatomy */}

{/* BEGIN: do-dont */}

## Do's and don'ts

### Do

- Give each `FooterCard` a single topic and a `title` that names it, so the footer's headings stay
  meaningful in a screen reader's heading list
- Set `external` on links that leave the site, and say so in the link's `name`, e.g. "Instagram
  (opens in a new tab)"

### Don't

- Never place a `FooterCard` on a light surface: it carries readable-on-dark text and paints no
  background of its own
- Don't repeat a link `name` within one card; users scanning a list of links can't tell two
  identical labels apart

{/* END: do-dont */}
