# FooterCard

{/* BEGIN: general */}

A titled column of links for a page footer — "Discover us", "Our social media", or any other
grouped set of footer navigation.

```tsx
import { FooterCard } from '@droppy/design-system'
```

<Canvas of={FooterCardStories.Default} />

## Features

- `title` renders as an `<h2>` via `Heading` — a footer typically stacks several `FooterCard`s
  side by side, each its own labeled section.
- `links` is an ordered list of `{ name, href?, external?, render? }`. Each renders through `Link`,
  so it inherits the same `render` escape hatch for router-aware links.
- `external` links get `target="_blank"` and `rel="noopener noreferrer"` automatically.
- `children` renders after the link list (or on its own, when `links` is omitted) — for content
  that isn't a link, like app store badges or a short paragraph.
- FooterCard is designed to live on a dark footer surface, so it owns its own text color —
  `--ds-color-text-on-inverse` on the root, `currentColor` on links — rather than leaving each
  consumer to restate it.
- Merges any incoming `className` with its own `droppy-FooterCard` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- Inside a page footer, grouping a titled set of links — site navigation, social links, legal
  links.
- Only on a dark footer surface (e.g. `--ds-color-surface-inverse`). FooterCard's text color
  assumes that context and doesn't paint a background of its own — it's a text-on-dark component,
  not a self-contained dark panel.

## When not to use

- A single standalone link — use [Link](?path=/docs/actions-link--docs) directly.
- A trail of ancestor pages — use [Breadcrumb](?path=/docs/navigation-breadcrumb--docs).

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### Text color on dark footers

FooterCard assumes it sits on a dark footer surface and sets its own text color to
`--ds-color-text-on-inverse` accordingly — a consumer doesn't need to override `color` to make it
readable. Links inherit the same color via `currentColor` down an ancestor-qualified chain
(`.droppy-FooterCard .droppy-FooterCard-link`), so a consumer's own CSS reset can't strip it. The
story below renders against `--ds-color-surface-inverse`, the token a footer would actually use.

<Canvas of={FooterCardStories.Default} />

### External links

An item marked `external` opens in a new tab with `rel="noopener noreferrer"` — the escaping
hatch and the security attribute travel together, so a caller can't get one without the other.

<Canvas of={FooterCardStories.ExternalLinks} />

### Router links per item

`render` swaps the default `<a>` for a router-aware link on a single item, the same way
`Breadcrumb` composes its crumbs.

## Anatomy

A heading above a list of links. The list disappears entirely when `links` is empty, so a column of `children` alone renders no stray `<ul>`.

| Title | `title`     | `<h2>`                          | The column heading                                 |
| List  | `list`      | `<ul>`                          | Absent when `links` is empty                       |
| Item  | `item`      | `<li>`                          | One per entry                                      |
| Link  | `link`      | `<a>` (or the `render` element) | Rendered through `Link`                            |

## Do's and don'ts

### Do

- Use `FooterCard` only on a dark footer surface — it's a text-on-dark component, not a
  self-contained dark panel.
- Keep one `FooterCard` per topic so the footer's headings stay meaningful.

### Don't

- Don't place `FooterCard` on a light surface — its text color assumes a dark background.
- Avoid `FooterCard` for a single standalone link — use
  [Link](?path=/docs/actions-link--docs).

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

Each link is a real `<a>` (or the router element passed via `render`) — standard link keyboard
behaviour applies, no custom handling.

- **ARIA:** the title is a real `<h2>`, so assistive tech can jump between footer sections by
  heading; links sit in a plain `<ul>`.
- **Screen reader:** announced as a heading followed by a list of links.
- **You must provide:** nothing further — heading level and list semantics are built in. Make sure
  each footer only has one `FooterCard` per topic so the headings stay meaningful.

{/* END: a11y */}

{/* BEGIN: brand */}

## Brand

The on-dark text color is a documented usage principle, not a styling accident: a `FooterCard`
only goes in a footer, and the footer surface is always dark, so the component carries its
readable-on-dark text color directly and assumes that context. Placing it on a light surface
breaks the principle rather than a style. The decision log records how this went from implicit
default to stated rule.

{/* END: brand */}

{/* BEGIN: styling */}

## Styling

| Token                        | Used for                 |
| ---------------------------- | ------------------------ |
| `--ds-color-text-on-inverse` | Default text color       |
| `--ds-space-xs`              | Space below the title    |
| `--ds-space-2xs`             | Space between list items |

FooterCard is built for the dark footer surface (`--ds-color-surface-inverse`) and sets its own
text color rather than leaving contrast to each consumer — no wrapper override is needed to make
its text readable. Links inherit their color from the card via `currentColor`, so overriding
`--ds-color-text-on-inverse` (or setting `color` on a wrapping element) re-colors both the title
and the links together. `className` merges with the component's own `droppy-FooterCard` class.

## Decision log

- **2020-09**: Mealdrop's footer and its FooterCard columns were created with styled-components ([base work](https://github.com/yannbf/mealdrop/commit/78dc77923c528c1006e3501d2ee11447cba1143a)).
- **2021-05**: the footer title became an `<h2>` for document structure while keeping heading-4-sized type via a CSS override — semantic level deliberately decoupled from visual scale, a pairing Droppy still honours ([footer card fix](https://github.com/yannbf/mealdrop/commit/2d2303d1758c7d703fb20f5077ad212499fe980d)).
- **2026-08**: ported onto the Heading and Link primitives with links as a `{name, href?, external?, render?}` array; the port initially dropped the title-size override and relied on implicit colour inheritance — the title rendered at heading-2 scale ([#14](https://github.com/yannbf/droppy-ds/issues/14)) and links went invisible under a consumer `* { color }` reset ([#13](https://github.com/yannbf/droppy-ds/issues/13)) — both fixed by pinning the title to `--ds-type-size-lg` and restating `color: inherit` down the list chain with ancestor-qualified selectors ([initial commit](https://github.com/yannbf/droppy-ds/commit/00b19b5a1be01ae266251a71bd074e28ad8cd267), [hardening commit](https://github.com/yannbf/droppy-ds/commit/21cbe802a1e3c6262b4e3fd56baf883f61038bb7)).
- **2026-08**: the on-dark text color was formalized as an intentional usage principle instead of an implicit default. MealDrop's adoption still had to wrap the component (`styled(DsFooterCard) { color: var(--ds-color-text-on-inverse) }`) to get readable text, even though the component already carried that color — Steve's review of the port called it out: "If a FooterCard only goes in Footer and Footer is always dark, then it's safe to do that directly in Droppy and document it as a brand principle" ([mealdrop#65 review](https://github.com/yannbf/mealdrop/pull/65), [#297](https://github.com/yannbf/droppy-ds/issues/297)). Docs now state the dark-footer assumption directly, and the stories decorator renders against the canonical `--ds-color-surface-inverse` token instead of a hardcoded color, closing [#284](https://github.com/yannbf/droppy-ds/issues/284).
- **Built on `Heading` (level 2) and `Link` for each item.** Droppy supplies the props, the theme classes, and the copy around it.

{/* END: history */}

## Known issues & open questions

- [#282](https://github.com/yannbf/droppy-ds/issues/282): `external` links set `target`/`rel` but give assistive tech no cue that a new tab opens. **Workaround:** use `render` to supply an anchor with visually-hidden "(opens in new tab)" text.
- [#283](https://github.com/yannbf/droppy-ds/issues/283): list items are keyed by the visible `name` — two links sharing a label trigger React key collisions and can misreconcile on updates. **Workaround:** keep `name` values unique within a `links` array.
- [#285](https://github.com/yannbf/droppy-ds/issues/285): the title is `<Heading level={2}>` down-sized by an ancestor-qualified CSS override instead of Heading's own `size` prop — `size={4}` exists for exactly this, so the CSS specificity fight looks unnecessary; open question whether the override is deliberate.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
