# Tabs

{/* BEGIN: anatomy */}

## Anatomy

A tab row with its indicator, and one panel per tab. The list is flat — `tabs` renders the whole set, so there is no `Tabs.Tab`/`Tabs.Panel` to compose by hand.

<Canvas of={TabsStories.Anatomy} />

| Part      | `data-part` | Renders    | Purpose                                                                  |
| :-------- | :---------- | :--------- | :----------------------------------------------------------------------- |
| Root      | `root`      | `<div>`    | Owns the active value and links tabs to panels                           |
| List      | `list`      | `<div>`    | The `role="tablist"` row                                                 |
| Tab       | `tab`       | `<button>` | One per entry, carrying `aria-selected`                                  |
| Indicator | `indicator` | `<span>`   | The sliding underline; writes the active tab's position as CSS variables |
| Viewport  | `viewport`  | `<div>`    | Wraps the panels                                                         |
| Panel     | `panel`     | `<div>`    | One per tab; only the active one shows                                   |

{/* END: anatomy */}

{/* BEGIN: do-dont */}

## Do's and don'ts

### Do

- Label each tab with the noun its panel holds, e.g. "Reviews" rather than "More": `label` is both
  the visible text and the accessible name
- Give every tab a stable `value` that doesn't move with list order, since it is what links a tab
  to its panel
- Keep the tab row short enough to fit one line at mobile width, so no choice is hidden off the
  edge

### Don't

- Don't put a view's primary action in a tab that isn't open by default; it stays invisible until
  someone switches
- Avoid `disabled` tabs where the reason isn't visible: a tab users can see but never reach needs
  an explanation beside it

{/* END: do-dont */}
