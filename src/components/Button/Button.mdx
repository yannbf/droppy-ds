# Button

{/* BEGIN: anatomy */}

## Anatomy

The control and its optional leading glyph. There is no label part: `children` render directly inside the button, spaced from the icon with `gap` rather than a spacer node.

<Canvas of={ButtonStories.Anatomy} />

| Part | `data-part` | Renders    | Purpose                                                      |
| :--- | :---------- | :--------- | :----------------------------------------------------------- |
| Root | `root`      | `<button>` | Fill, radius, focus ring, and the disabled state             |
| Icon | `icon`      | `<svg>`    | The optional leading glyph, rendered only when `icon` is set |

{/* END: anatomy */}

## Do's and don'ts

### Do

- Give icon-only buttons (`icon` with no `children`) an `aria-label`: the icon is `aria-hidden`,
  so nothing else names the button
- Write the label as the action users are taking, in sentence case, e.g. "Add to cart" rather than
  "ADD TO CART" or "Submit"
- Keep one `large` primary action per view, so the page offers a single obvious next step

### Don't

- Never recolour a primary button: the [brand guidelines](?path=/docs/brand-guidelines--docs) put
  "the primary button" on the grey ramp, and teal is "not for buttons, links, or interface chrome"
- Don't nest a `Button` inside another control: two controls in one spot confuse keyboard focus
  and screen readers
- Avoid `disabled` for an action that is merely in flight: a disabled button leaves the tab order
  and the accessibility tree, dropping focus mid-task
