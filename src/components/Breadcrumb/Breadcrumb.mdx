{/* BEGIN: general */}

A trail of ancestor pages leading to the current one — categories, restaurants, anything with a
browsable hierarchy above it.

```tsx
import { Breadcrumb } from '@droppy/design-system'
```

## Features

- `items` is an ordered list of `{ label, href? }` — a crumb with no `href` renders as plain text
  rather than a link, for the current page or any ancestor with nowhere to go.
- No router dependency: crumbs render a plain `<a href>` by default. Pass `render` on an item to
  swap in a router-aware link instead (see below) — the design system itself never imports a
  router.
- The last item always carries `aria-current="page"`, whether it renders as a link or as text.
- A `/` separator sits between crumbs, hidden from assistive tech (`aria-hidden`) since the list
  markup already conveys order.
- Merges any incoming `className` with its own `droppy-Breadcrumb` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- Above a page reached by drilling into a category, a restaurant, or any other browsable
  hierarchy, so the visitor can jump back to an ancestor in one click.

## When not to use

- On a page with no hierarchy above it — a plain link back to the parent page reads more
  honestly than a one-crumb trail implying a hierarchy that isn't there.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### The current page

The last crumb carries `aria-current="page"` whether it renders as a link or as plain text, and
the whole trail sits inside a `<nav aria-label="breadcrumb">` landmark — the semantics Mealdrop's
`div`/`p` version had none of.

### Router links via `render`

Item `render` swaps the default `<a>` for a router-aware link, so the design system carries no
router dependency of its own.

{/* END: behavior */}

## Anatomy

A labelled landmark around an ordered list, one item per crumb. A crumb renders as a link when it has a destination and as text when it does not — usually the last one.

<Canvas of={BreadcrumbStories.Anatomy} />

| Part      | `data-part` | Renders  | Purpose                                    |
| :-------- | :---------- | :------- | :----------------------------------------- |
| Root      | `root`      | `<nav>`  | The `aria-label="breadcrumb"` landmark     |
| List      | `list`      | `<ol>`   | Crumb order is document order              |
| Item      | `item`      | `<li>`   | Holds one crumb and its trailing separator |
| Link      | `link`      | `<a>`    | A crumb with a destination                 |
| Text      | `text`      | `<span>` | A crumb without one                        |
| Separator | `separator` | `<span>` | The `aria-hidden` slash; never announced   |

## Do's and don'ts

### Do

- List `items` from the site root down, with the current page last: the final crumb is
  automatically marked `aria-current="page"`
- Label each crumb with the destination's own page title, so the trail matches what users see when
  they arrive

### Don't

- Don't point the last crumb's `href` somewhere else: it is announced as the current page
- Don't skip crumbs when a page has the same base `href` but loads specific child content based on a query param

{/* END: do-dont */}

## Keyboard & screen reader

Each linked crumb is a real `<a>` (or the router element passed via `render`) — standard link
keyboard behaviour applies, no custom handling.

- **ARIA:** the root is `<nav aria-label="breadcrumb">` wrapping an `<ol>`; the last crumb carries
  `aria-current="page"`.
- **Screen reader:** announced as a "breadcrumb" navigation landmark containing an ordered list;
  the current crumb is announced as the current page.
- **You must provide:** nothing further — the landmark, list semantics, and current-page marking
  are all built in.

## API reference

<ArgTypes of={BreadcrumbStories} />

### `items`

The trail, as `{ label, href?, render? }`. The last item is the current page.

A single crumb is the current page on its own, and no separator renders.

### Item `render`

Cloned with the crumb's link class and, on the last item, `aria-current`. The passed element owns
its own destination, so `href` is dropped rather than spread on top of it.

### `className`

Merged onto the root alongside the component's own `droppy-Breadcrumb` class.

## Decision log

- **2025-03**: Breadcrumb was born in Mealdrop with an `items: {label, path?}[]` array API — items with a `path` render as underlined router links, the trailing item without one as plain text for the current page — introduced alongside its first stories ([Breadcrumb added](https://github.com/yannbf/mealdrop/commit/14cf17a324a99c4744eec1495810f96d4e17bc5d), [mealdrop #42](https://github.com/yannbf/mealdrop/pull/42)).
- **2026-07**: Droppy's Breadcrumb dropped the react-router coupling: crumbs became `{label, href?}` items rendered as plain `<a>` inside `<nav aria-label="breadcrumb">` with `aria-current="page"` on the last, with a per-item `render` prop as the escape hatch for router-aware links; `font-weight: lighter` became `--ds-type-weight-regular` since the body face ships no lighter cut and the keyword resolved to regular anyway ([migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-08**: a visual-parity audit found a crumb rendered through `Link` losing Breadcrumb's own styling on compiled-bundle order (two single-class rules tie), and proposed ancestor-qualified rules (`.droppy-Breadcrumb .droppy-Breadcrumb-link`) so specificity decides instead; fixing it by zeroing `Link`'s own specificity with `:where()` was explicitly rejected, since that would let any consumer `* { color }` reset override links everywhere. The PR was closed unmerged, so the defect is tracked as [#12](https://github.com/yannbf/droppy-ds/issues/12) ([droppy-ds #8](https://github.com/yannbf/droppy-ds/pull/8)).
- **Built on a plain `<nav>` and `<ol>`; each crumb is an `<a>` by default.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#12](https://github.com/yannbf/droppy-ds/issues/12): A crumb rendered through Link loses Breadcrumb's styling on bundle order. **Workaround:** ancestor-qualify the crumb rules in app CSS (`.droppy-Breadcrumb .droppy-Breadcrumb-link`).
- [#126](https://github.com/yannbf/droppy-ds/issues/126): `render` items are cloned with an explicit `href: undefined` prop that clobbers link components spreading rest-props after their own `href`. **Workaround:** in the custom link component, spread incoming props before setting href (`<a {...rest} href={to} />`) or destructure the incoming `href` away.
- [#130](https://github.com/yannbf/droppy-ds/issues/130): landmark label is hard-coded English `aria-label="breadcrumb"` with no way to localize or override it. **Workaround** (hacky): set the attribute imperatively after mount via a wrapper ref's querySelector('nav').
- [#135](https://github.com/yannbf/droppy-ds/issues/135): current page gets no visual marking when the last crumb is a link — no `[aria-current]` styling exists anywhere in the package. **Workaround:** app CSS on `.droppy-Breadcrumb-link[aria-current='page']`, or omit href/render on the last item.
- [#141](https://github.com/yannbf/droppy-ds/issues/141): duplicate `href` values produce duplicate React keys, with no consumer-controllable key. **Workaround:** keep hrefs unique, omit href instead of placeholder values, use root-relative hrefs.
- [#145](https://github.com/yannbf/droppy-ds/issues/145): items without `href` — including the documented router `render` pattern — get index-coupled keys that remount crumbs, while docs wrongly claim `href` is ignored on `render` items. **Workaround:** pass a unique href alongside render purely as a key stabilizer, or keep trail updates append/truncate-only.
- [#149](https://github.com/yannbf/droppy-ds/issues/149): labels are visually lowercased by an undocumented `text-transform: lowercase`; the MDX styling table is also missing a token. **Workaround:** app CSS `text-transform: none` on the two crumb classes; treat the CSS file as the token source of truth.
- [#153](https://github.com/yannbf/droppy-ds/issues/153): `items={[]}` still renders the nav landmark and its vertical margin. **Workaround:** guard with `items.length > 0 &&` in the consumer, or a `:has()`-based CSS rule.
- [#158](https://github.com/yannbf/droppy-ds/issues/158): links are the only interactive elements without the design system's focus ring — keyboard focus falls back to the UA default outline. **Workaround:** app CSS adding `box-shadow: var(--ds-shadow-focus)` on `.droppy-Breadcrumb-link:focus-visible`.
- [#162](https://github.com/yannbf/droppy-ds/issues/162): A long unbroken label cannot wrap or shrink — the trail overflows the viewport horizontally. **Workaround:** app CSS `min-width: 0` on items plus `overflow-wrap: anywhere` (or ellipsis) on crumb text, or truncate labels upstream.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
