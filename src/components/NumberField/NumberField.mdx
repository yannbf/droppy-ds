# NumberField

{/* BEGIN: general */}

A typeable numeric input with increment/decrement buttons and pointer scrub, for a quantity or
amount that also needs a keyboard or direct-entry path.

```tsx
import { NumberField } from '@droppy/design-system'
```

labelled via [`Field`](https://base-ui.com/react/components/field) the same way
[Input](?path=/docs/forms-input-input--docs) is.

<Canvas of={NumberFieldStories.Default} />

## Features

- **Typeable, unlike a plain stepper.** Type a value directly, use the arrow keys, click the
  increment/decrement buttons, or drag the label to scrub — four ways to reach the same value.
- **`min`/`max`/`step` clamp interactive changes.** The stepper buttons disable once a bound is
  reached rather than wrapping around.
- **The label doubles as a scrub area.** Dragging it left/right changes the value with the
  pointer, without needing to focus the input first.
- **`value`/`defaultValue`/`onValueChange` follow Base UI's controlled/uncontrolled pattern** —
  omit `value` for an uncontrolled field, or pass both `value` and `onValueChange` to control it.
- Merges any incoming `className` onto the root, alongside the theme layer's own class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A quantity or amount where the caller can't predict every value in advance, or where keyboard
  and direct-entry access matter — a cart quantity with a wide range, a price, a form field
  counting units of something.

## When not to use

- A small, bounded range where tap-tap increments are the whole interaction and typing isn't
  expected — reach for [QuantityStepper](?path=/docs/forms-input-quantitystepper--docs) instead;
  it is the simpler, button-only sibling of this component.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

Three ways in, not one: type a value, press the buttons, or drag the label itself — the scrub area
sits behind the label text. That third route is what separates this from
[QuantityStepper](?path=/docs/forms-input-quantitystepper--docs), which only does tap-tap
increments.

## Do's and don'ts

### Do

- Always pass `label`: it is the field's accessible name as well as its visible one, and it
  doubles as the scrub handle
- Set `min` and `max` to the real bounds of what users may enter, so the stepper buttons disable
  at the edges instead of accepting an impossible value
- Set `step` to the increment the quantity actually moves in, e.g. 0.5 for kilograms rather than
  the default 1

### Don't

- Don't treat drag-to-scrub as the way users reach a value: it is pointer-only, so typing and the
  arrow keys have to get there too
- Don't leave `max` unset on a field bounded by stock or capacity; without it the buttons never
  disable and an over-limit value reaches the handler

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

| Key / interaction                     | Context | Action                                             |
| ------------------------------------- | ------- | -------------------------------------------------- |
| Arrow Up / Arrow Down (input focused) | any     | Steps the value by `step`                          |
| Home / End (input focused)            | any     | Jumps to `min`/`max`, when set                     |
| Type digits                           | any     | Replaces the value as parsed input                 |
| Click Increment / Decrement           | any     | Steps the value by `step`; disables at `min`/`max` |
| Drag the label                        | any     | Scrubs the value with pointer movement             |

- **ARIA:** the increment and decrement buttons carry their own accessible names ("Increase" /
  "Decrease") from Base UI; the input is a `textbox` associated with the label through `Field`.
- **Screen reader:** the current value is read as the input's own value; the stepper buttons
  announce as disabled once a bound is reached.
- **You must provide:** `label` — without it the field has no accessible name.

classes — this component adds no styling of its own beyond forwarding `className` to the root.

## Known issues & open questions

- [#94](https://github.com/yannbf/droppy-ds/issues/94): touch: the label blocks page scrolling entirely, and horizontal swipes on it can change the value. **Workaround:** app CSS `pointer-events: none` on `.NumberFieldScrubArea` restores page scrolling, at the cost of scrub and label-click-to-focus; or omit `label` and label externally via `id`.
- [#96](https://github.com/yannbf/droppy-ds/issues/96): clicking the label fires onValueCommitted with the unchanged value (reason 'scrub'). **Workaround:** dedupe in the handler — ignore onValueCommitted calls whose value equals the last committed value, or skip reason 'scrub' events with an unchanged value.
- [#99](https://github.com/yannbf/droppy-ds/issues/99): mouse scrubbing hides the pointer but renders no replacement cursor — the drag is invisible in Chromium/Firefox. **Workaround:** app CSS on the global `.NumberFieldScrubAreaCursor` class — give the span an explicit size and a visible background/glyph.
- [#102](https://github.com/yannbf/droppy-ds/issues/102): className, style, and ref land on an inner div — not the outermost element — and inputRef targets Base UI's hidden input. **Workaround:** wrap in your own element for layout/ref (or target `.droppy-Field` from app CSS), and reach the visible input via `id` or `querySelector("input[type=\"text\"]")` instead of `inputRef`.
- [#105](https://github.com/yannbf/droppy-ds/issues/105): docs omit that onValueChange fires null and that controlled-empty requires value=&#123;null&#125;, not undefined. **Workaround:** type controlled state as number | null, represent empty as null (never undefined), and null-check before numeric operations.
- [#107](https://github.com/yannbf/droppy-ds/issues/107): aria-label / aria-labelledby / aria-describedby type-check but are inert — a field without the label prop has no accessible name. **Workaround:** pass `id` and supply your own (optionally visually hidden) external `<label htmlFor>`; descriptions require a post-mount DOM patch on the input.
- [#110](https://github.com/yannbf/droppy-ds/issues/110): accessible strings "Increase", "Decrease", and "Number field" are hardcoded English with no way to localize them. **Workaround** (fragile): post-mount DOM setAttribute patch of the three ARIA strings from a wrapper ref, or bypass the wrapper and compose Base UI parts directly.
- [#113](https://github.com/yannbf/droppy-ds/issues/113): no 'use client' directive — passing function props from a React Server Component module throws at the Base UI boundary. **Workaround:** add 'use client' to the consuming module, or create a single client re-export file and import the DS through it in server trees.
- [#310](https://github.com/yannbf/droppy-ds/issues/310): `label` is typed optional, but omitting it leaves the field with no accessible name. **Workaround:** pass `label` at every call site.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
- [#138](https://github.com/yannbf/droppy-ds/issues/138): theme chrome is bound to unnamespaced global classes (`.Button`, `.Input`, `.FieldRoot`, …) with no cascade layer, so host-app CSS collides in both directions.
