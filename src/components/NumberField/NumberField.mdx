# NumberField

{/* BEGIN: anatomy */}

## Anatomy

A `Field` wrapper for the label association, a scrub area holding the label, and a group of decrement, input, and increment. The label being inside the scrub area is what makes dragging it change the value.

<Canvas of={NumberFieldStories.Anatomy} />

| Part       | `data-part` | Renders    | Purpose                                             |
| :--------- | :---------- | :--------- | :-------------------------------------------------- |
| Field      | `field`     | `<div>`    | Base UI's `Field.Root`, associating label and input |
| Root       | `root`      | `<div>`    | Owns the value, the bounds, and the formatting      |
| Scrub area | `scrub`     | `<span>`   | Wraps the label; dragging it steps the value        |
| Label      | `label`     | `<label>`  | The visible label and accessible name               |
| Group      | `group`     | `<div>`    | Holds the buttons and the input                     |
| Decrement  | `decrement` | `<button>` | Disabled at `min`                                   |
| Input      | `input`     | `<input>`  | The typeable control                                |
| Increment  | `increment` | `<button>` | Disabled at `max`                                   |

{/* END: anatomy */}

## Do's and don'ts

### Do

- Always pass `label`: it is the field's accessible name as well as its visible one, and it
  doubles as the scrub handle
- Set `min` and `max` to the real bounds of what users may enter, so the stepper buttons disable
  at the edges instead of accepting an impossible value
- Set `step` to the increment the quantity actually moves in, e.g. 0.5 for kilograms rather than
  the default 1

### Don't

- Don't treat drag-to-scrub as the way users reach a value: it is pointer-only, so typing and the
  arrow keys have to get there too
- Don't leave `max` unset on a field bounded by stock or capacity; without it the buttons never
  disable and an over-limit value reaches the handler

{/* END: do-dont */}
