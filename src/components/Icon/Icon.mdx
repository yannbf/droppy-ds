# Icon

{/* BEGIN: anatomy */}

## Anatomy

`Icon` is a single-part component: one `<svg>`, whose paths come from the bundled set that `name` indexes into. Nothing inside it is addressable.

<Canvas of={IconStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                               |
| :--- | :---------- | :------ | :-------------------------------------------------------------------- |
| Root | `root`      | `<svg>` | The glyph: viewBox, stroke colour, and the width/height/minWidth trio |

{/* END: anatomy */}

## Decision log

- **2025-03**: the `name` prop was retyped from plain `string` to an `IconName` string-literal union (arrow-right, arrow-left, cross, cart, minus, plus, moon, sun, star), making invalid icon names a compile-time error; Droppy inherits this closed, typed icon set ([IconName union](https://github.com/yannbf/mealdrop/commit/14cf17a324a99c4744eec1495810f96d4e17bc5d), [mealdrop #42](https://github.com/yannbf/mealdrop/pull/42)).
- **Built on a plain `<svg>` element.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#200](https://github.com/yannbf/droppy-ds/issues/200): unknown `name` throws a TypeError during render — no guard or fallback, crashes the subtree (and the whole request on SSR). **Workaround:** validate dynamic names against the exported `iconNames` array before rendering, and keep data-driven regions inside an error boundary.
- [#204](https://github.com/yannbf/droppy-ds/issues/204): `star` glyph is inconsistent with the rest of the set: fill-drawn path renders as a ~1.2px hairline outline, and its edge-to-edge 20-unit viewBox makes it optically oversized. **Workaround:** pass style=&#123;&#123; fill: 'currentColor', stroke: 'none' &#125;&#125; to paint it as the filled star, and render it slightly smaller (~5/6) to compensate for the unpadded viewBox.
- [#206](https://github.com/yannbf/droppy-ds/issues/206): forwarded `stroke` and `strokeWidth` props are silent no-ops (class rule beats the attribute; inner `<g strokeWidth={2}>` beats inheritance — except on `star`). **Workaround:** use the `color` prop or style=&#123;&#123; stroke &#125;&#125; for colour, and a CSS rule targeting the inner g/path (which beats the presentation attribute) for stroke width.
- [#209](https://github.com/yannbf/droppy-ds/issues/209): default stroke is pinned to the global icon token and ignores surrounding text colour — invisible on the theme's own inverse surface in light mode. **Workaround:** pass color="currentColor" (inline style beats the class rule) or add an app CSS override scoping `stroke: currentcolor` to the coloured context.
- [#210](https://github.com/yannbf/droppy-ds/issues/210): `width`/`height` props are accepted but visually inert — the size-derived inline style always wins. **Workaround:** use the `size` prop, or pass dimensions through `style` (merged last, wins over the internal inline sizing).
- [#212](https://github.com/yannbf/droppy-ds/issues/212): consumer-passed children (e.g. `<title>` for an accessible name) are silently discarded. **Workaround:** label the wrapping control instead, or pass aria-hidden=&#123;false&#125; role="img" aria-label — forwarded props override the hardcoded defaults.
- [#214](https://github.com/yannbf/droppy-ds/issues/214): A unitless numeric string (`size="24"`) silently voids all inline sizing — the icon looks right but loses the flex-squeeze guard and style precedence. **Workaround:** always pass a number or a unit-bearing string (e.g. size=&#123;24&#125; or size="1.5rem"), never a unitless numeric string.
- [#215](https://github.com/yannbf/droppy-ds/issues/215): glyphs paint nothing wherever the package stylesheet doesn't reach (shadow DOM, iframes, pre-CSS paint) — the SVG markup carries no colour. **Workaround:** pass color (rendered as inline style, works in any context) or adopt the package stylesheet inside the shadow root/iframe.
- [#216](https://github.com/yannbf/droppy-ds/issues/216): docs claim `aria-hidden`/`focusable` are applied "always", but `{...rest}` spreads after them and consumer props override. **Workaround:** none needed — treat the attributes as overridable defaults; use the override deliberately and avoid spreading arbitrary prop bags if the decorative guarantee matters.
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only).
