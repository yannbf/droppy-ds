# Icon

{/* BEGIN: general */}

The icon set, inlined as SVG so it renders wherever the component tree renders, with no static
asset to serve.

```tsx
import { Icon } from '@droppy/design-system'
```

<Canvas of={IconStories.Default} />

## Features

- Every icon is inlined rather than referenced from a sprite sheet — a package can't assume the
  consuming app serves a given static file, and `<use xlink:href>` against a cross-origin sprite
  fails outright.
- Decorative by default: the root `<svg>` carries `aria-hidden="true"` and `focusable="false"`,
  so it never intercepts focus or gets announced on its own.
- `size` accepts a number or a string, sets width, height, and `minWidth` together so a flex
  parent can't squeeze it, and defaults to `1.5rem`.
- `color` overrides the stroke inline, which beats the class rule — unset, the icon uses the
  theme's icon token and flips with the theme automatically.
- Merges any incoming `className` with its own `droppy-Icon` class.

## How it works

### Decorative by default

Every icon renders `aria-hidden="true"` and `focusable="false"`, so it never reaches the
accessibility tree. The control an icon sits inside is what carries the accessible name — reach
for `Icon` directly and that naming becomes your job.

<Canvas of={IconStories.DecorativeByDefault} />

### Colour

Unset, the stroke follows `--ds-color-icon-default` and changes with the theme. Passing `color`
sets the stroke inline instead, which wins over the class rule.

## Anatomy

`Icon` is a single-part component: one `<svg>`, whose paths come from the bundled set that `name` indexes into. Nothing inside it is addressable.

| Part | `data-part` | Renders | Purpose                                                               |
| :--- | :---------- | :------ | :-------------------------------------------------------------------- |
| Root | `root`      | `<svg>` | The glyph: viewBox, stroke colour, and the width/height/minWidth trio |
