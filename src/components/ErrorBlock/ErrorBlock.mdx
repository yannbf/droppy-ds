# ErrorBlock

{/* BEGIN: anatomy */}

## Anatomy

Title, optional illustration, body, and one action — in that DOM order. The heading comes first in the DOM even though the illustration sits above it visually, so the announcement leads with what happened.

<Canvas of={ErrorBlockStories.Anatomy} />

| Part         | `data-part`    | Renders    | Purpose                                                 |
| :----------- | :------------- | :--------- | :------------------------------------------------------ |
| Root         | `root`         | `<div>`    | The centred column holding the whole message            |
| Title        | `title`        | `<h2>`     | What happened                                           |
| Illustration | `illustration` | `<div>`    | The optional slot; absent, nothing renders in its place |
| Body         | `body`         | `<p>`      | The explanation                                         |
| Action       | `action`       | `<button>` | The single recovery action                              |

{/* END: anatomy */}

{/* BEGIN: do-dont */}

## Do's and don'ts

### Do

- Write `buttonText` that names the recovery, e.g. "Try again" or "See all restaurants"
- Say what users can do next in `body`, not only what went wrong
- Hide decorative `illustration`s from assistive tech

### Don't

- Don't reuse one generic `title` for every failure: an empty search and a failed request need
  different wording to be actionable
- Avoid an `ErrorBlock` with nowhere to go; the recovery action is the whole point of the block
- When an error results from user action, avoid `illustration` or `body` content that can be perceived as accusatory or mocking; sound supportive instead

{/* END: do-dont */}
