# ErrorBlock

A titled message with an optional illustration and a single recovery action — an empty
category, a 404, a failed request.

- **Import:** `import { ErrorBlock } from '@droppy/design-system'`
- **Built on:** [Heading](?path=/docs/components-heading--docs), [Body](?path=/docs/components-body--docs),
  and [Button](?path=/docs/components-button--docs) — no Base UI primitive of its own.

<Canvas of={ErrorBlockStories.Default} />

## Features

- A required `title`, `body`, `buttonText`, and `onButtonClick` — every instance ends in exactly
  one action.
- `illustration` takes any `ReactNode` — an inline SVG, an image, an animation the caller drives
  itself — or nothing at all.
- `className` merges onto the root element, so wrapping it in `styled()` or adding utility
  classes composes instead of stripping the design system's styling.

## When to use

- An empty result set that still needs a way forward — no restaurants in a category, an empty
  search.
- A 404 or 500 branch of a page, paired with a way back — home, retry, or the previous list.

## When not to use

- A shape-matching placeholder while content is still on its way — use
  [Skeleton](?path=/docs/components-skeleton--docs) instead. `ErrorBlock` is for a state that has
  already resolved to "nothing here," not one still loading.

## How it works

`ErrorBlock` stacks its four parts in a column: the `title` as a level-2 `Heading`, the
`illustration` slot (only rendered when one is passed), the `body` as plain `Body` copy, and the
action as a `Button`. Composition, not configuration — the illustration is whatever the caller
renders, so a Lottie animation, a static image, or an inline SVG all work the same way.

<Canvas of={ErrorBlockStories.WithoutIllustration} />

## Keyboard & screen reader

- **ARIA:** none of its own — `Heading` renders a real `<h2>`, so it's reachable via a screen
  reader's heading-navigation tools, and `Button` renders a real `<button>` with native keyboard
  activation.
- **Screen reader:** the title is announced as a heading, the body as ordinary text, and the
  button by its `buttonText`.
- **You must provide:** a `buttonText` that describes the destination or retry action on its own
  — "Try again" or "See all restaurants" rather than "Click here" — since it's the only
  interactive element in the block.

## Styling

| Token           | Used for                                         |
| --------------- | ------------------------------------------------ |
| `--ds-space-md` | Vertical padding on the root element             |
| `--ds-space-sm` | Space above the illustration, when one is passed |

`Heading`, `Body`, and `Button` read their own tokens independently — see each component's docs
for those.

## Decision log

- **2026-07**: the `image` prop was renamed `illustration` and made optional: the Lottie player and its animation JSON are application assets, so the slot takes any node or nothing rather than baking a player dependency into the package; the rest of the API (title, body, buttonText, onButtonClick) carried over unchanged from Mealdrop, and the inner gap moved from 20px to `--ds-space-sm` (24px) because spacing.m has no exact token and the scale is the source of truth ([migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md), [wave 2 commit](https://github.com/yannbf/droppy-ds/commit/4b20c0eca2ee66fb2a7f05aef13522621430fe67), [mealdrop #63](https://github.com/yannbf/mealdrop/pull/63)).
- **2026-08**: ErrorBlock was adopted in the agentic-reference Mealdrop as part of the 17-component, 49.6%-coverage baseline ([mealdrop #66](https://github.com/yannbf/mealdrop/pull/66)).

## Known issues & open questions

- [#58](https://github.com/yannbf/droppy-ds/issues/58): appears silently to assistive tech: no status semantics, and the closed prop surface (no ref, rest props, or aria passthrough) blocks both standard remedies (open; has workaround: wrap in your own div with role="status"/tabIndex=&#123;-1&#125;/ref and manage announcement and focus at the wrapper).
- [#60](https://github.com/yannbf/droppy-ds/issues/60): vertical spacing between title, body, and button comes from UA paragraph margins — collapses to zero under common CSS resets (open; has workaround: add `.droppy-ErrorBlock { gap: var(--ds-space-sm) }` in app CSS (optionally zero the illustration's margin-top)).
- [#62](https://github.com/yannbf/droppy-ds/issues/62): heading level is hard-coded to h2 with no override, so the block cannot fit the host page's heading outline (open; has workaround: hand-compose Heading (with the right level) + Body + Button instead of ErrorBlock where h2 breaks the outline).
- [#64](https://github.com/yannbf/droppy-ds/issues/64): no way to disable the action or represent a retry in flight — repeated clicks fire onButtonClick each time (open; has workaround: guard re-entrancy in the onButtonClick handler, or swap in Spinner/hand-composed parts while the retry is pending).
- [#66](https://github.com/yannbf/droppy-ds/issues/66): wrapped title or body text renders start-aligned inside the otherwise centered composition (open; has workaround: add `text-align: center` on the root via className or `.droppy-ErrorBlock` in app CSS).
- [#69](https://github.com/yannbf/droppy-ds/issues/69): the recovery action can only be a &lt;button&gt; — navigation recoveries ("go home", "see all") cannot render as links (open; has workaround: router.push in the handler (loses link affordances), or hand-compose with an &lt;a className="Button droppy-Button"&gt;).
- [#71](https://github.com/yannbf/droppy-ds/issues/71): prop types are narrower than what the parts render: string-only title/body/buttonText, and onButtonClick hides the MouseEvent it is actually called with (open; has workaround: cast ReactNode/event-taking handlers at the call site (runtime supports both), or hand-compose the exported parts).
- [#73](https://github.com/yannbf/droppy-ds/issues/73): an illustration node that renders nothing still mounts the spacer wrapper, adding a phantom 24px gap (open; has workaround: pass undefined until the illustration will actually paint, or `.droppy-ErrorBlock-illustration:empty { margin-top: 0 }`).
- [#76](https://github.com/yannbf/droppy-ds/issues/76): docs never say the illustration must carry its own alt/aria-hidden — the slot exposes whatever is passed to screen readers (open; has workaround: put aria-hidden="true" / alt="" (or a meaningful alt) on the illustration node you pass in).
- [#78](https://github.com/yannbf/droppy-ds/issues/78): documented example sets SVG fills with var() in presentation attributes, which browsers reject — the circles paint black (open; has workaround: use style=&#123;&#123; fill: 'var(…)' &#125;&#125; or CSS classes for SVG fills in your own illustrations instead of copying the example).
