# Heading

{/* BEGIN: when-to-use */}

## When to use

- A page or section title that should appear in the document outline and in a screen reader's heading-navigation list.
- The title slot of a Base UI `Dialog` or `Drawer`, via `render` — the ref forwarding exists specifically so those components can point `aria-labelledby` at the rendered heading tag.

## When not to use

- To style text for size alone — a stat number in a dashboard tile, for instance — without giving it heading semantics, use plain text with the theme's type tokens instead. `Heading` always renders a real `<h1>`–`<h5>`, so using it purely for its size adds a heading to the outline that isn't one.
- To make a heading "look right" against its neighbors, don't skip `level`s (jumping from 1 to 4, say). Keep levels sequential and adjust spacing or layout instead — screen reader users navigate by level, and a skipped level reads as a missing section.

{/* END: when-to-use */}

{/* BEGIN: anatomy */}

## Anatomy

`Heading` is a single-part component. It forwards its ref and remaining props, so composition wrappers — Base UI's `Dialog.Title`, `Drawer.Title` — can point `aria-labelledby` at the real heading element.

<Canvas of={HeadingStories.Anatomy} />

| Part | `data-part` | Renders       | Purpose                                            |
| :--- | :---------- | :------------ | :------------------------------------------------- |
| Root | `root`      | `<h1>`–`<h5>` | The heading, tagged by `level` and sized by `size` |
