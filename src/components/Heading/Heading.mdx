# Heading

Display type for page and section titles, rendered as a real semantic heading.

- **Import:** `import { Heading } from '@droppy/design-system'`
- **Built on:** a plain `<h1>`–`<h5>` element — no Base UI primitive.

<Canvas of={HeadingStories.Levels} />

## Features

- **`level` picks the tag, and the size by default** — `level={3}` renders an actual `<h3>` at the matching size step. Pass `size` separately to keep the tag at one level while the visual size follows another, for a heading that needs to look smaller (or larger) than its place in the outline.
- **Forwards its ref and the rest of its props**, so composition wrappers — Base UI's `Drawer.Title`, `Dialog.Title` — can wire `aria-labelledby` to the real heading element instead of a wrapper `<div>`.
- **Levels 1–2 use tighter "display" tracking**; levels 3–5 stay at the default tracking, matching the difference between a page-level display size and an ordinary section heading.
- **`className` merges onto the element** rather than replacing it, so wrapping a `Heading` in `styled()` or adding utility classes composes instead of stripping Droppy's own type styles.

## When to use

- A page or section title that should appear in the document outline and in a screen reader's heading-navigation list.
- The title slot of a Base UI `Dialog` or `Drawer`, via `render` — the ref forwarding exists specifically so those components can point `aria-labelledby` at the rendered heading tag.

## When not to use

- To style text for size alone — a stat number in a dashboard tile, for instance — without giving it heading semantics, use plain text with the theme's type tokens instead. `Heading` always renders a real `<h1>`–`<h5>`, so using it purely for its size adds a heading to the outline that isn't one.
- To make a heading "look right" against its neighbors, don't skip `level`s (jumping from 1 to 4, say). Keep levels sequential and adjust spacing or layout instead — screen reader users navigate by level, and a skipped level reads as a missing section.

## How it works

### `level` renders the matching tag

The same prop that picks the rendered element also picks the size step by default — `level={3}` is an `<h3>` at the level-3 size, not a styled `<div>`.

<Canvas of={HeadingStories.RendersMatchingTag} />

### `size` decouples the visual size from the tag

`size` defaults to `level`, so most call sites never set it. Pass it explicitly to pick a different visual size while `level` keeps choosing the rendered tag — a card title that needs to stay an `<h2>` in the outline but look like a level-4 heading, for instance. Dense layouts (card titles, compact sections) are the usual reason to reach for it; the outline still reads `level`.

<Canvas of={HeadingStories.SizeDecoupledFromLevel} />

### Type scale across levels

Levels 1 and 2 are the display sizes and get tighter letter-spacing; level 3 and below are section headings and use the default tracking. Level 5 has its own size step, so it never falls back to whatever type size happens to surround it.

## Keyboard & screen reader

`Heading` has no interactive behavior — it's a static element, not a control.

- **ARIA:** none needed. The native tag (`<h1>`–`<h5>`) already carries the `heading` role and its level; there is no extra wiring to get wrong.
- **Screen reader:** announced as "heading level N, `<text>`," and listed in heading-navigation tools such as NVDA's Elements List or VoiceOver's rotor.
- **You must provide:** a sequential `level` order (don't skip levels) and exactly one `h1` per page, so the outline a screen reader user navigates by stays meaningful — `size` only changes the visual step, so this holds whether or not you set it.

## Styling

`Heading` reads these tokens directly:

| Token                                             | Used for                                                                     |
| ------------------------------------------------- | ---------------------------------------------------------------------------- |
| `--ds-color-text-primary`                         | Text color                                                                   |
| `--ds-type-family-heading`                        | Font family                                                                  |
| `--ds-type-tracking-default`                      | Letter-spacing, size steps 3–5                                               |
| `--ds-type-tracking-display`                      | Letter-spacing, size steps 1–2                                               |
| `--ds-type-size-3xl` / `2xl` / `xl` / `lg` / `md` | Font size, size steps 1 through 5 respectively — `size` if set, else `level` |

`className` is merged onto the rendered tag, so it composes with the tokens above rather than overriding them wholesale.

- **2026-07**: Sidebar's Drawer.Title renders Heading so the drawer has a real accessible name, which forced Heading to forward ref and rest props (id, `aria-*`) so the aria-labelledby id actually reaches the DOM ([heading commit](https://github.com/yannbf/mealdrop/commit/40f20f7aba828e146634d88e58cbb324541645c4), [sidebar commit](https://github.com/yannbf/mealdrop/commit/6d946fcf90684f3d87b79d6d081fbf29d41f26ce)).
- **2026-07**: a `size` prop decoupled visual scale from semantic `level` — level picks the tag, size (defaulting to level) picks the scale, e.g. `<Heading level={2} size={4}>` — replacing the four styled(Heading) wrappers Mealdrop used to shrink correctly-levelled headings; level 5 also got a real size rule, where Mealdrop's scale had stopped at 4 ([size prop replaces wrappers](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).

## Known issues & open questions

- [#61](https://github.com/yannbf/droppy-ds/issues/61): setting `id` on a Heading used as a Dialog/Drawer Title render element silently breaks `aria-labelledby` (open; has workaround: put the `id` on `Dialog.Title`/`Drawer.Title` itself, never on the Heading render element).
- [#63](https://github.com/yannbf/droppy-ds/issues/63): no font-weight declaration — weight tokens never reach it, and CSS resets (Tailwind preflight) silently render headings at weight 400 (open; has workaround: app CSS rule `.droppy-Heading { font-weight: var(--ds-type-weight-bold, 700) }` after the DS stylesheet).
- [#65](https://github.com/yannbf/droppy-ds/issues/65): no line-height declaration — theme containers with fixed rem line-heights (.DialogTitle 1.5rem, .AccordionPanel 1.25rem) render overlapping heading text (open; has workaround: set an explicit line-height on the Heading (inline style, utility class, or app-level `.droppy-Heading` rule)).
- [#67](https://github.com/yannbf/droppy-ds/issues/67): theme fonts are subset to Latin-1 only — latin-ext characters (Polish, Czech, Romanian, Hungarian, Turkish, Vietnamese) render in the fallback typeface mid-word (open; has workaround: add app-level @font-face rules for the missing subsets under the same family names, or override the family tokens).
- [#68](https://github.com/yannbf/droppy-ds/issues/68): styles.css hard-codes fonts.gstatic.com URLs — heading typeface depends on a third-party Google fetch (strict CSP/offline breakage, GDPR exposure) (open; has workaround: allowlist fonts.gstatic.com in CSP, or shadow the @font-face rules with self-hosted ones / override the family tokens).
- [#70](https://github.com/yannbf/droppy-ds/issues/70): default `level={1}` turns Base UI's `<h2>` title slot into a page-level `<h1>` (open; has workaround: always pass an explicit `level` (e.g. `level={2}`) when using Heading in a title render slot).
- [#72](https://github.com/yannbf/droppy-ds/issues/72): docs tell consumers to title Modal/Sidebar with a ref-forwarded Heading, but neither component exposes any such slot (open; has workaround: use Modal's aria-label / Sidebar's string title as documented on those components; compose Base UI Dialog directly if a real labelledby link is needed).
- [#74](https://github.com/yannbf/droppy-ds/issues/74): docs attribute the tighter display tracking to `level` 1-2, but the code ties it to the visual size step (`size ?? level`) (open; has workaround: none needed once understood — tracking follows `size ?? level`; set letter-spacing explicitly to force a different pairing).
- [#75](https://github.com/yannbf/droppy-ds/issues/75): h6 is inexpressible, and out-of-union `level`/`size` values (6, 0) silently render with no size-step styling (open; has workaround: stay within levels 1-5, or hand-roll an h6 with the base class plus an explicit size token).
- [#77](https://github.com/yannbf/droppy-ds/issues/77): display tracking is a literal -2px, so it does not scale with the rem-based sizes (cramped under html font-size 62.5% or text-only zoom) (open; has workaround: override `--ds-type-tracking-display` to an em-based value (e.g. -0.045em) in app CSS).
