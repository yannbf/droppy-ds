# Body

{/* BEGIN: anatomy */}

## Anatomy

`Body` is a single-part component. The tag it renders follows `type`; `size` and `fontWeight` only add classes, so all four elements can land on the same scale.

<Canvas of={BodyStories.Anatomy} />

| Part | `data-part` | Renders                                       | Purpose                                                |
| :--- | :---------- | :-------------------------------------------- | :----------------------------------------------------- |
| Root | `root`      | `<p>` / `<span>` / `<label>` / `<figcaption>` | The text element, carrying the size and weight classes |

{/* END: anatomy */}

{/* BEGIN: history */}

## Decision log

- **2026-07**: the brand extraction fixed typography as two faces with clear jobs — Hind for body and UI text, Montserrat reserved for headings — which Body's styles encode and the [Typography tokens](?path=/docs/design-tokens-typography--docs) document as the system rule.
- **2026-08**: Body carried Mealdrop's polymorphic text API into Droppy — a `type` prop selecting the rendered element ('p' | 'span' | 'label' | 'figcaption'), an S/XS/XXS size scale, and named font weights (regular/medium/bold/black) ([migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747)).
- **Built on a plain `<p>`, `<span>`, `<label>`, or `<figcaption>` element — no Base UI.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#33](https://github.com/yannbf/droppy-ds/issues/33): props are not correlated with `type` — wrong-element attributes compile silently, and inline handlers/callback refs fail with TS7006. **Workaround:** annotate handler/ref parameters explicitly and enforce type="label"+htmlFor pairing by convention or a typed wrapper.
- [#36](https://github.com/yannbf/droppy-ds/issues/36): `display: block` forces the `span` and `label` variants out of inline flow. **Workaround:** pass a consumer className that sets display:inline; app CSS loaded after the DS stylesheet wins at equal specificity.
- [#39](https://github.com/yannbf/droppy-ds/issues/39): `fontWeight="bold"` and `"black"` have no real font faces — Hind ships only at 400/500, so both render as identical synthesized bold. **Workaround:** add an app-level @font-face for Hind 700 to fix bold; black has no Hind cut and needs a font-family override.
- [#42](https://github.com/yannbf/droppy-ds/issues/42): literal `color` values silently break in dark mode, which the stylesheet activates from OS preference without any app opt-in. **Workaround:** pass --ds-color-\* tokens to `color` instead of literals, or pin the scheme with data-theme on the root.
- [#44](https://github.com/yannbf/droppy-ds/issues/44): `type="label"` does not match the design system's own field labels — different color token, size, capitalization, and no focus-active state. **Workaround** (partial): size="S" + color="var(--ds-color-text-label)" approximates the resting look; capitalization and focus state need custom CSS.
- [#46](https://github.com/yannbf/droppy-ds/issues/46): no margin reset — the default `<p>` keeps user-agent margins, unlike Heading, so spacing depends on the host app's CSS reset. **Workaround:** use a global CSS reset or an app rule like `.droppy-Body { margin: 0 }`.
- [#48](https://github.com/yannbf/droppy-ds/issues/48): no line-height — paragraph leading is inherited from the host app, contradicting the Typography doc's per-component claim. **Workaround:** set line-height in app CSS globally on .droppy-Body or per instance.
- [#49](https://github.com/yannbf/droppy-ds/issues/49): default `<p>` plus unconstrained ReactNode children — block-level children produce invalid HTML and SSR hydration errors, undocumented. **Workaround:** use type="span"/"figcaption" for rich children, or keep default-&lt;p&gt; children to phrasing content.
- [#51](https://github.com/yannbf/droppy-ds/issues/51): required `children` makes `dangerouslySetInnerHTML` a trap — the natural call is a compile error and the compiling variant throws at runtime. **Workaround:** pass children=&#123;undefined&#125; alongside dangerouslySetInnerHTML, or use a raw element with the droppy-Body class.
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only).
