A horizontally scrolling row of items — restaurant cards, category tiles — showing a fixed number
per breakpoint, with drag, wheel-gesture, and arrow navigation.

```tsx
import { Carousel } from '@droppy/design-system'
```

and the design system's own `IconButton` for the arrows.

## Features

- `itemsPerView` sets how many items are visible per breakpoint (mobile, tablet, desktop) —
  fractional values (e.g. `1.2`) are valid, and peek the next item at the edge.
- `slidesToScroll` sets how many items an arrow click advances per breakpoint (defaults to `1` at
  every breakpoint).
- Dragging works on both mouse and touch. Horizontal wheel / trackpad scrolling and shift+scroll
  also move the carousel; vertical scrolling still scrolls the page.
- A slide dims to `opacity: 0.5` once it's no longer (almost) fully in view, signaling there's more
  to scroll to without hiding it outright.
- Arrows only render once there's somewhere to go in that direction, and only appear at the desktop
  breakpoint — smaller screens scroll by dragging instead.
- Merges any incoming `className` with its own `droppy-Carousel` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A horizontally browsable row of same-shaped items where showing a fixed count per breakpoint
  matters more than showing everything at once — a restaurant list, a category rail.

## When not to use

- A small, fixed set of items that all fit comfortably in the available width — a plain flex or
  grid row needs no carousel machinery.

{/* END: when-to-use */}

{/* BEGIN: behavior */}

## How it works

### Arrows appear only where there is somewhere to go

Neither arrow renders when that direction can't scroll, and both are desktop-only besides —
smaller screens scroll by dragging or by horizontal wheel gesture.

### Dimmed slides

Slides that aren't almost fully visible drop to 0.5 opacity, so a partially scrolled row signals
there is more to reach rather than looking clipped.

{/* END: behavior */}

## Anatomy

A rail wrapping a clipped viewport and the track inside it, one wrapper per child, with the arrows as siblings of the viewport. The per-breakpoint counts reach the CSS as custom properties rather than inline widths, so the stylesheet owns the breakpoints.

<Canvas of={CarouselStories.Anatomy} />

| Part      | `data-part` | Renders    | Purpose                                                    |
| :-------- | :---------- | :--------- | :--------------------------------------------------------- |
| Root      | `root`      | `<div>`    | Carries the item counts as CSS custom properties           |
| Viewport  | `viewport`  | `<div>`    | The clipped window Embla drives                            |
| Container | `container` | `<div>`    | The track that slides horizontally                         |
| Slide     | `slide`     | `<div>`    | One wrapper per child; dims when not almost fully in view  |
| Nav       | `nav`       | `<button>` | Previous/next; mounted only when that direction can scroll |

## Do's and don'ts

### Do

- Set `itemsPerView` so part of the next item shows at the trailing edge on each breakpoint: the
  cut-off item is what tells users there is more to scroll
- Match `slidesToScroll` to `itemsPerView` when users are meant to page through the row rather
  than nudge it one item at a time
- Give the surrounding region an accessible name, e.g. a heading directly above it; the carousel
  labels only its own arrows

### Don't

- Don't put anything users must see in a slide that starts off-screen: arrows render on desktop
  only, so smaller screens rely on dragging
- Don't lean on the dimming of partly-scrolled slides to carry meaning; it signals scrollability,
  not state

{/* END: do-dont */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

Arrow buttons are real `<button>`s (via `IconButton`) with `aria-label="Previous"` /
`aria-label="Next"`, focusable and operable with keyboard and screen readers. The scroll track
itself is drag-only, matching the same tradeoff most carousel implementations make; each slide's
own content remains independently focusable and readable in document order.

- **ARIA:** none beyond the labeled arrow buttons — the design system leaves the region's
  accessible name to the caller.
- **Screen reader:** slide content is read in document order regardless of which slides are
  currently dimmed or in view.
- **You must provide:** an accessible label for the carousel region as a whole, if the surrounding
  page needs one (e.g. wrap it with `aria-label` or a preceding heading).

Arrow buttons use `IconButton`'s own styling (see [IconButton](?path=/docs/actions-iconbutton--docs)) —
deliberately not theme-reactive, so they stay legible over arbitrary imagery. `className` merges
with the component's own `droppy-Carousel` class.

## API reference

<ArgTypes of={CarouselStories} />

### `children`

Become the slides — one wrapper is added per child.

### `itemsPerView`

How many items fit per breakpoint, mobile-first. Fractions are deliberate: `1.2` shows a sliver of
the next tile so the row reads as scrollable.

### `slidesToScroll`

How many items each arrow click advances, per breakpoint. Defaults to 1.

### `className`

Merged onto the root alongside the component's own `droppy-Carousel` class.

## Decision log

- **2020**: Mealdrop's carousel churned through libraries early — a faulty react-carousel release, then a wholesale switch — and picked up its one durable behaviour: vertical touch panning passes through the track, the ancestor of Droppy's `touch-action: pan-y pinch-zoom` ([faulty version](https://github.com/yannbf/mealdrop/commit/7c955a6a25477039341c287e2a77f71bb456c58b), [library switch](https://github.com/yannbf/mealdrop/commit/47705de1f77c6a379276d3dffa985d552d33ce66), [vertical pan fix](https://github.com/yannbf/mealdrop/commit/6290a9585f5b102a2ff0cd6adebc94ce8ef061ac)).
- **2025-04**: an accessibility pass gave the arrows their "Previous"/"Next" labels, asserted in Storybook play tests — Droppy inherits the labelled-arrows contract ([a11y pass](https://github.com/yannbf/mealdrop/commit/51b060508116f56e9c3e48301adb0b0562305b12)).
- **2026-08**: ported from Mealdrop's Embla-based carousel onto token-driven CSS, adding `embla-carousel-react` and `embla-carousel-wheel-gestures` as dependencies; the old per-breakpoint prop bag (responsive objects, custom arrow slots, `removeArrowOnDeviceType`) collapsed to `itemsPerView: {mobile, tablet, desktop}` plus optional `slidesToScroll`, with fixed IconButton arrows that render only at desktop and only when there is somewhere to scroll, and a new dimming affordance that fades partially-visible slides to half opacity ([initial commit](https://github.com/yannbf/droppy-ds/commit/00b19b5a1be01ae266251a71bd074e28ad8cd267)).
- **Built on [Embla Carousel](https://www.embla-carousel.com/) with the wheel-gestures plugin,.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#271](https://github.com/yannbf/droppy-ds/issues/271): below the 1024px breakpoint the arrows are `display: none` and the track is pointer-only, so keyboard users have no supported way to bring off-screen slides into view. **Workaround:** none within the component; provide app-level controls or keep essential content out of the overflow.
- [#272](https://github.com/yannbf/droppy-ds/issues/272): dimmed slides sit at 50% opacity, which can push AA-passing text below contrast — and the stories disable the a11y addon's color-contrast rule, so CI never flags it. **Workaround:** verify dimmed-state contrast for your slide content manually.
- [#273](https://github.com/yannbf/droppy-ds/issues/273): the arrow labels are hardcoded English "Previous"/"Next" with no localization path. No workaround — the labels are not props and the arrows cannot be replaced.
- [#274](https://github.com/yannbf/droppy-ds/issues/274): no RTL support — Embla is never passed `direction: 'rtl'` and the arrow positions are physical `left`/`right`, so in an RTL locale the arrows sit and scroll against reading order. **Workaround:** none exposed; requires wrapping or forking.
- [#275](https://github.com/yannbf/droppy-ds/issues/275): `itemsPerView` values are not validated — `0` produces `calc(100% / 0)` and a degenerate layout. **Workaround:** pass integers of at least 1.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
