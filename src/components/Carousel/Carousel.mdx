# Carousel

{/* BEGIN: general */}

A horizontally scrolling row of items — restaurant cards, category tiles — showing a fixed number
per breakpoint, with drag, wheel-gesture, and arrow navigation.

```tsx
import { Carousel } from '@droppy/design-system'
```

and the design system's own `IconButton` for the arrows.

<Canvas of={CarouselStories.Default} />

## Features

- `itemsPerView` sets how many items are visible per breakpoint (mobile, tablet, desktop) —
  fractional values (e.g. `1.2`) are valid, and peek the next item at the edge.
- `slidesToScroll` sets how many items an arrow click advances per breakpoint (defaults to `1` at
  every breakpoint).
- Dragging works on both mouse and touch. Horizontal wheel / trackpad scrolling and shift+scroll
  also move the carousel; vertical scrolling still scrolls the page.
- A slide dims to `opacity: 0.5` once it's no longer (almost) fully in view, signaling there's more
  to scroll to without hiding it outright.
- Arrows only render once there's somewhere to go in that direction, and only appear at the desktop
  breakpoint — smaller screens scroll by dragging instead.
- Merges any incoming `className` with its own `droppy-Carousel` class.

{/* END: general */}

{/* BEGIN: when-to-use */}

## When to use

- A horizontally browsable row of same-shaped items where showing a fixed count per breakpoint
  matters more than showing everything at once — a restaurant list, a category rail.

## When not to use

- A small, fixed set of items that all fit comfortably in the available width — a plain flex or
  grid row needs no carousel machinery.

{/* END: when-to-use */}

## How it works

### Arrows appear only where there is somewhere to go

Neither arrow renders when that direction can't scroll, and both are desktop-only besides —
smaller screens scroll by dragging or by horizontal wheel gesture.

<Canvas of={CarouselStories.ArrowsOnlyWhenThereIsSomewhereToGo} />

### Dimmed slides

Slides that aren't almost fully visible drop to 0.5 opacity, so a partially scrolled row signals
there is more to reach rather than looking clipped.

## Anatomy

A rail wrapping a clipped viewport and the track inside it, one wrapper per child, with the arrows as siblings of the viewport. The per-breakpoint counts reach the CSS as custom properties rather than inline widths, so the stylesheet owns the breakpoints.

<Canvas of={CarouselStories.Anatomy} />

| Part      | `data-part` | Renders    | Purpose                                                    |
| :-------- | :---------- | :--------- | :--------------------------------------------------------- |
| Root      | `root`      | `<div>`    | Carries the item counts as CSS custom properties           |
| Viewport  | `viewport`  | `<div>`    | The clipped window Embla drives                            |
| Container | `container` | `<div>`    | The track that slides horizontally                         |
| Slide     | `slide`     | `<div>`    | One wrapper per child; dims when not almost fully in view  |
| Nav       | `nav`       | `<button>` | Previous/next; mounted only when that direction can scroll |

## Keyboard & screen reader

Arrow buttons are real `<button>`s (via `IconButton`) with `aria-label="Previous"` /
`aria-label="Next"`, focusable and operable with keyboard and screen readers. The scroll track
itself is drag-only, matching the same tradeoff most carousel implementations make; each slide's
own content remains independently focusable and readable in document order.

- **ARIA:** none beyond the labeled arrow buttons — the design system leaves the region's
  accessible name to the caller.
- **Screen reader:** slide content is read in document order regardless of which slides are
  currently dimmed or in view.
- **You must provide:** an accessible label for the carousel region as a whole, if the surrounding
  page needs one (e.g. wrap it with `aria-label` or a preceding heading).

## Styling

| Token              | Used for                                 |
| ------------------ | ---------------------------------------- |
| `--ds-space-sm`    | Gutter between slides                    |
| `--ds-motion-base` | Dim/undim transition duration for slides |

Arrow buttons use `IconButton`'s own styling (see [IconButton](?path=/docs/actions-iconbutton--docs)) —
deliberately not theme-reactive, so they stay legible over arbitrary imagery. `className` merges
with the component's own `droppy-Carousel` class.
