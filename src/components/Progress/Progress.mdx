# Progress

A track-and-fill indicator for progress through a known or unknown-length task — an upload, an
export, a multi-step process.

- **Import:** `import { Progress } from '@droppy/design-system'`
- **Built on:** Base UI [`Progress`](https://base-ui.com/react/components/progress).

<Canvas of={ProgressStories.Default} />

## Features

- **`value` (default `null`) drives the fill** — a number renders a determinate bar; `null` or
  omitting it renders an indeterminate sweep, for a wait whose length or step count isn't known.
- **`Label` and `Value` parts**, shown via `label` and `showValue` — the value defaults to a
  formatted percentage of the range, with no extra markup from the caller.
- **`max` (default `100`) supports arbitrary ranges**; the reported percentage and ARIA
  attributes are always computed against it.
- Merges any incoming `className` onto the root, alongside the theme layer's own class.

## When to use

- Progress through a task the caller can express as a `value`/`max` ratio — a file upload, an
  export, a wizard's steps.
- A wait with no known duration or step count — pass `value={null}` for the indeterminate variant
  instead of reaching for a separate component.

## When not to use

- Droppy's own hand-rolled [ProgressBar](?path=/docs/components-progressbar--docs) is the
  simpler, determinate-only sibling of this component — reach for it when a plain track-and-fill
  with a title/copy the caller renders separately is enough, and the `Label`/`Value` parts or
  indeterminate mode aren't needed.
- For a content placeholder shown while data is loading, rather than a task's own progress, use
  [Skeleton](?path=/docs/components-skeleton--docs).
- For a small, unlabelled spinner next to a button or inline action, use
  [Spinner](?path=/docs/components-spinner--docs) instead — it carries no value or percentage.

## Keyboard & screen reader

`Progress` is a passive, non-interactive indicator — there is no keyboard interaction to
document.

- **ARIA:** `role="progressbar"` with `aria-valuenow`/`aria-valuemin`/`aria-valuemax` in
  determinate mode; `aria-valuenow` is omitted entirely when indeterminate.
- **Screen reader:** announced as a progress indicator with its current value, where the
  containing screen reader supports live region updates on attribute changes.
- **You must provide:** `label` — without it the progress bar has no accessible name.

## Styling

Colors, track/fill radius, and the indeterminate sweep animation come from the theme layer's
`Progress*` classes — this component adds no styling of its own beyond forwarding `className` to
the root.

## Known issues & open questions

- [#227](https://github.com/yannbf/droppy-ds/issues/227): indeterminate sweep completes a full loop every 300ms and reads as a strobe (open; has workaround: override `animation-duration` on `.ProgressIndicator[data-indeterminate]` in app CSS loaded after the design system stylesheet).
- [#228](https://github.com/yannbf/droppy-ds/issues/228): indeterminate sweep ignores prefers-reduced-motion (open; has workaround: add a `@media (prefers-reduced-motion: reduce)` rule in app CSS setting `animation: none` on `.ProgressIndicator[data-indeterminate]`).
- [#229](https://github.com/yannbf/droppy-ds/issues/229): A long unbroken label widens the grid columns, stretching the track past the component's own width (open; has workaround: override the root to `minmax(0, 1fr)` columns and add wrapping/truncation to `.ProgressLabel` in app CSS, or shorten the label string before passing it).
- [#230](https://github.com/yannbf/droppy-ds/issues/230): degenerate ranges are not validated: max=&#123;0&#125; reports data-complete, max=&#123;NaN&#125; emits aria-valuenow="NaN" (open; has workaround: validate the total in app code — render `value={null}` (or nothing) until the total is known and finite, and pass `max={undefined}` to fall back to the default of 100).
- [#231](https://github.com/yannbf/droppy-ds/issues/231): showValue text is formatted with the runtime locale, producing SSR hydration mismatches (open; has workaround: pass an explicit `locale` prop (it is forwarded to Base UI's root), or set `showValue={false}` and render the value text yourself).
- [#232](https://github.com/yannbf/droppy-ds/issues/232): root has a fixed width of 15rem, so the bar does not fill its container (open; has workaround: pass `style={{ width: '100%' }}` (forwarded to the root as an inline style) or a `className` with a width, loaded after the design system stylesheet).
- [#233](https://github.com/yannbf/droppy-ds/issues/233): default value text rounds to whole percent, and `format` formats the raw value rather than the percentage (open; has workaround: express the range as a fraction (`value={done / total} max={1}`) when using `format` for percentages, or floor the value / render your own text).
- [#234](https://github.com/yannbf/droppy-ds/issues/234): --ds-color-progress-track and --ds-color-progress-fill have no effect on this component (open; has workaround: re-point `.ProgressTrack` / `.ProgressIndicator` at the progress-named tokens in app CSS loaded after the design system stylesheet).
- [#235](https://github.com/yannbf/droppy-ds/issues/235): JSX children type-check but are silently discarded (open; has workaround: none needed at runtime — use the `label` prop (accepts any ReactNode) or render sibling elements yourself; nothing enforces this at the type level).
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode (open, systemic).
