# ProgressBar

{/* BEGIN: anatomy */}

## Anatomy

Two parts: the track carries the `progressbar` role and the whole ARIA range, and the fill is a plain width-driven sibling underneath it with no semantics of its own. There is no label part — the copy around the bar is the caller's own markup.

<Canvas of={ProgressBarStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                              |
| :--- | :---------- | :------ | :------------------------------------------------------------------- |
| Root | `root`      | `<div>` | `role="progressbar"` with `aria-valuenow`/`-min`/`-max` and the name |
| Fill | `fill`      | `<div>` | The width-driven bar; purely visual                                  |

## Decision log

- **2026-07**: the checkout progress fill (`--ds-color-action-progress`) deliberately follows `--ds-color-action-primary` in both themes — the [brand guidelines](?path=/docs/brand-guidelines--docs) re-decide colour roles per theme (soft green even becomes the primary button in dark mode) rather than inverting light values.
- **2026-07**: ProgressBar — ported from Mealdrop's checkout step indicator — stays a plain `role="progressbar"` track-and-fill for progress through a known number of steps, deliberately coexisting with the richer Progress rather than being replaced by it ([additional components commit](https://github.com/yannbf/droppy-ds/commit/1fba4ce05fa71da8aa51a56ea60dae6b218c1868), [Progress.tsx](https://github.com/yannbf/droppy-ds/blob/main/src/components/Progress/Progress.tsx)).
- **Built on a plain `<div>` element.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#115](https://github.com/yannbf/droppy-ds/issues/115): value=&#123;NaN&#125; renders a completely full bar and aria-valuenow="NaN". **Workaround:** guard the prop at the call site with `Number.isFinite(v) ? v : 0`, or use `Progress` with `value={null}` while the total is unknown.
- [#118](https://github.com/yannbf/droppy-ds/issues/118): children are accepted by the props type but never rendered. **Workaround:** render step copy as a sibling element next to `<ProgressBar />` rather than as its children.
- [#120](https://github.com/yannbf/droppy-ds/issues/120): max is not validated: max=&#123;0&#125; and negative max emit an invalid ARIA range. **Workaround:** normalise `max` at the call site (`max={Math.max(1, total)}`) or skip rendering the bar when the total is 0 or unknown.
- [#123](https://github.com/yannbf/droppy-ds/issues/123): label is optional in the types although the docs and role="progressbar" require it. **Workaround:** always pass `label`, or supply `aria-labelledby` through the rest props, and add an axe/jsx-a11y check to catch omissions.
- [#128](https://github.com/yannbf/droppy-ds/issues/128): no aria-valuetext, so step-based bars are announced as a percentage. **Workaround:** pass `aria-valuetext` through the rest props and keep it in sync with `value`/`max` yourself, or use `Progress`.
- [#132](https://github.com/yannbf/droppy-ds/issues/132): docs point indeterminate cases to Skeleton and never mention Progress or Spinner. **Workaround:** for unknown-duration waits use `Progress` with `value={null}` (or `Spinner`) despite the ProgressBar page pointing to Skeleton.
- [#136](https://github.com/yannbf/droppy-ds/issues/136): fill transition ignores prefers-reduced-motion. **Workaround:** app-level `@media (prefers-reduced-motion: reduce) { .droppy-ProgressBar-fill { transition: none } }`.
- [#142](https://github.com/yannbf/droppy-ds/issues/142): aria-valuenow/-min/-max passed as props override the computed values while the fill keeps its own. **Workaround:** never pass `aria-valuenow`/`-min`/`-max`; express state only through `value`/`max` (`aria-valuetext` and `aria-labelledby` remain safe).
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only).
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode.
