# ProgressBar

{/* BEGIN: when-to-use */}

## When to use

- Progress through a known, finite sequence — a wizard's steps, an upload's byte count, a form's
  page count — where the caller can compute a `value`/`max` ratio at any moment.

## When not to use

- For a wait with no known duration or step count — an indeterminate spinner reads honestly where
  a determinate bar would imply progress that isn't real. Use
  [Skeleton](?path=/docs/feedback-status-skeleton--docs) for a loading placeholder instead.

{/* END: when-to-use */}

{/* BEGIN: anatomy */}

## Anatomy

Two parts: the track carries the `progressbar` role and the whole ARIA range, and the fill is a plain width-driven sibling underneath it with no semantics of its own. There is no label part — the copy around the bar is the caller's own markup.

<Canvas of={ProgressBarStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                              |
| :--- | :---------- | :------ | :------------------------------------------------------------------- |
| Root | `root`      | `<div>` | `role="progressbar"` with `aria-valuenow`/`-min`/`-max` and the name |
| Fill | `fill`      | `<div>` | The width-driven bar; purely visual                                  |

{/* END: anatomy */}
