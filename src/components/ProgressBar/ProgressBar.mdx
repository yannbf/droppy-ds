# ProgressBar

{/* BEGIN: anatomy */}

## Anatomy

Two parts: the track carries the `progressbar` role and the whole ARIA range, and the fill is a plain width-driven sibling underneath it with no semantics of its own. There is no label part — the copy around the bar is the caller's own markup.

<Canvas of={ProgressBarStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                              |
| :--- | :---------- | :------ | :------------------------------------------------------------------- |
| Root | `root`      | `<div>` | `role="progressbar"` with `aria-valuenow`/`-min`/`-max` and the name |
| Fill | `fill`      | `<div>` | The width-driven bar; purely visual                                  |

{/* END: anatomy */}

{/* BEGIN: do-dont */}

## Do's and don'ts

### Do

- Always pass `label`: it is the only accessible name the bar gets, and any title rendered beside
  it isn't associated with the control
- Set `max` to the real total, e.g. the step count or the byte count, rather than converting to a
  percentage first

### Don't

- Never restyle the fill colour: the [brand guidelines](?path=/docs/brand-guidelines--docs)
  re-decide colour roles per theme, and the fill deliberately follows the theme's primary action
  in both
- Don't feed a `value` that can exceed `max` and rely on the clamp to hide it; the bar sits full
  while the task is still running
