# ProgressBar

A track-and-fill indicator for progress through a known number of steps — a multi-step checkout,
an upload, a form with a fixed page count.

- **Import:** `import { ProgressBar } from '@droppy/design-system'`
- **Built on:** a plain `<div>` element.

<Canvas of={ProgressBarStories.Mid} />

## Features

- `value` and `max` (default `100`) describe how far along the track the fill sits; `value` is
  clamped to `0`–`max` before it reaches the DOM, so an out-of-range prop can't overflow or
  invert the fill.
- `label` sets the accessible name on the track — the title and step copy around the bar
  ("Step 2 of 3") stay the caller's own markup, same as Mealdrop's `StepIndicator`.
- The fill's width transitions on change, so incrementing `value` sweeps rather than jumps.
- Merges any incoming `className` with its own `droppy-ProgressBar` class.

## When to use

- Progress through a known, finite sequence — a wizard's steps, an upload's byte count, a form's
  page count — where the caller can compute a `value`/`max` ratio at any moment.

## When not to use

- For a wait with no known duration or step count — an indeterminate spinner reads honestly where
  a determinate bar would imply progress that isn't real. Use
  [Skeleton](?path=/docs/components-skeleton--docs) for a loading placeholder instead.

### Clamping

A `value` past `max` (or below `0`) clamps to the nearest bound rather than overflowing the
track — the ARIA attributes and the rendered width always agree.

<Canvas of={ProgressBarStories.OverMaxClamps} />

## Keyboard & screen reader

`ProgressBar` is a passive, non-interactive indicator — there is no keyboard interaction to
document.

- **ARIA:** `role="progressbar"` with `aria-valuenow`, `aria-valuemin={0}`, and `aria-valuemax`
  on the root element; `aria-label` when `label` is set.
- **Screen reader:** announced as a progress indicator with its current value, when the
  containing screen reader supports live region updates on attribute changes.
- **You must provide:** `label` — without it the progress bar has no accessible name, and the
  title/copy the caller renders alongside it (as Mealdrop's `StepIndicator` does) isn't
  associated with the control by markup alone.

## Known issues & open questions

- [#115](https://github.com/yannbf/droppy-ds/issues/115): value=&#123;NaN&#125; renders a completely full bar and aria-valuenow="NaN" (open; has workaround: guard the prop at the call site with `Number.isFinite(v) ? v : 0`, or use `Progress` with `value={null}` while the total is unknown).
- [#118](https://github.com/yannbf/droppy-ds/issues/118): children are accepted by the props type but never rendered (open; has workaround: render step copy as a sibling element next to `<ProgressBar />` rather than as its children).
- [#120](https://github.com/yannbf/droppy-ds/issues/120): max is not validated: max=&#123;0&#125; and negative max emit an invalid ARIA range (open; has workaround: normalise `max` at the call site (`max={Math.max(1, total)}`) or skip rendering the bar when the total is 0 or unknown).
- [#123](https://github.com/yannbf/droppy-ds/issues/123): label is optional in the types although the docs and role="progressbar" require it (open; has workaround: always pass `label`, or supply `aria-labelledby` through the rest props, and add an axe/jsx-a11y check to catch omissions).
- [#128](https://github.com/yannbf/droppy-ds/issues/128): no aria-valuetext, so step-based bars are announced as a percentage (open; has workaround: pass `aria-valuetext` through the rest props and keep it in sync with `value`/`max` yourself, or use `Progress`).
- [#132](https://github.com/yannbf/droppy-ds/issues/132): docs point indeterminate cases to Skeleton and never mention Progress or Spinner (open; has workaround: for unknown-duration waits use `Progress` with `value={null}` (or `Spinner`) despite the ProgressBar page pointing to Skeleton).
- [#136](https://github.com/yannbf/droppy-ds/issues/136): fill transition ignores prefers-reduced-motion (open; has workaround: app-level `@media (prefers-reduced-motion: reduce) { .droppy-ProgressBar-fill { transition: none } }`).
- [#142](https://github.com/yannbf/droppy-ds/issues/142): aria-valuenow/-min/-max passed as props override the computed values while the fill keeps its own (open; has workaround: never pass `aria-valuenow`/`-min`/`-max`; express state only through `value`/`max` (`aria-valuetext` and `aria-labelledby` remain safe)).
- [#122](https://github.com/yannbf/droppy-ds/issues/122): components are plain function components, so `ref` type-checks but never attaches on React 18 (works on React 19 only) (open, systemic).
- [#129](https://github.com/yannbf/droppy-ds/issues/129): focus indicators are box-shadow-only with `outline: none`, so they vanish entirely in Windows High Contrast mode (open, systemic).
