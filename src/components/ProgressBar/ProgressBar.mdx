# ProgressBar

{/* BEGIN: anatomy */}

## Anatomy

Two parts: the track carries the `progressbar` role and the whole ARIA range, and the fill is a plain width-driven sibling underneath it with no semantics of its own. There is no label part — the copy around the bar is the caller's own markup.

<Canvas of={ProgressBarStories.Anatomy} />

| Part | `data-part` | Renders | Purpose                                                              |
| :--- | :---------- | :------ | :------------------------------------------------------------------- |
| Root | `root`      | `<div>` | `role="progressbar"` with `aria-valuenow`/`-min`/`-max` and the name |
| Fill | `fill`      | `<div>` | The width-driven bar; purely visual                                  |

{/* END: anatomy */}

{/* BEGIN: a11y */}

## Keyboard & screen reader

`ProgressBar` is a passive, non-interactive indicator — there is no keyboard interaction to
document.

- **ARIA:** `role="progressbar"` with `aria-valuenow`, `aria-valuemin={0}`, and `aria-valuemax`
  on the root element; `aria-label` when `label` is set.
- **Screen reader:** announced as a progress indicator with its current value, when the
  containing screen reader supports live region updates on attribute changes.
- **You must provide:** `label` — without it the progress bar has no accessible name, and the
  title/copy the caller renders alongside it (as Mealdrop's `StepIndicator` does) isn't
  associated with the control by markup alone.
