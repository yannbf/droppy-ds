# Tooltip

{/* BEGIN: anatomy */}

## Anatomy

Two parts, and only the trigger is reachable by the **Anatomy** panel: the popup is portalled to the document body, outside the canvas the panel scans, and `Tooltip` exposes no `container` prop the way `Modal` and `Sidebar` do. The popup still carries its `data-part` for anyone inspecting the DOM. Note the trigger is the child element itself — `Tooltip` renders no wrapper around it, so the layout stays flat.

<Canvas of={TooltipStories.Anatomy} />

| Part    | `data-part` | Renders           | Purpose                                     |
| :------ | :---------- | :---------------- | :------------------------------------------ |
| Trigger | `trigger`   | the child element | Rendered as the trigger itself, not wrapped |
| Popup   | `popup`     | `<div>`           | The tip; portalled outside the canvas       |

## Do's and don'ts

### Do

- Give the trigger its own accessible name, closely matching the tip: the popup carries no ARIA
  link to it and is never announced
- Keep `label` to a short phrase; the popup declares no max width, so a sentence stretches into a
  strip across the viewport
- Pass a single element as `children`, as it becomes the trigger itself rather than being wrapped

### Don't

- Don't put anything users need inside a `Tooltip`: it never opens on touch, and screen readers
  never read it
- Don't attach a `Tooltip` to a disabled control; a disabled button takes neither focus nor hover,
  so the tip never appears
- Avoid a `label` that restates the trigger's visible text, as a tip repeating the button teaches
  nothing
