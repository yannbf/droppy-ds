# Input

{/* BEGIN: when-to-use */}

## When to use

- Any single-line text field in a form — name, email, phone, postcode.
- A field whose validation message needs to reserve its layout space in advance, so an error appearing or clearing never reflows the fields around it.

## When not to use

- To let someone pick from a short, known list rather than type a value, use [Select](?path=/docs/forms-input-select--docs) instead — a select can't return a value the list doesn't contain, which is often what you want.
- For multi-line content, `Input` renders a single `<input>` and has no multi-line mode — reach for Base UI's `Field.Control render={<textarea />}` directly instead of stretching this component past a single line.

{/* END: when-to-use */}

{/* BEGIN: anatomy */}

## Anatomy

A field root wrapping a label, the control, and an always-mounted error slot. The slot is the unusual part: it stays in the DOM holding a non-breaking space when there is no message, which is what reserves the height.

<Canvas of={InputStories.Anatomy} />

| Part    | `data-part` | Renders   | Purpose                                                          |
| :------ | :---------- | :-------- | :--------------------------------------------------------------- |
| Root    | `root`      | `<div>`   | Base UI's `Field.Root`, wiring label, control and error together |
| Label   | `label`     | `<label>` | Absent when `label` is empty                                     |
| Control | `control`   | `<input>` | The control itself; `className` lands here                       |
| Error   | `error`     | `<div>`   | Always mounted, so showing a message never moves the layout      |

{/* END: anatomy */}
