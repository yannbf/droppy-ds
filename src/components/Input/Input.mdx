# Input

{/* BEGIN: general */}

A labelled text field with a reserved slot for its validation message.

```tsx
import { Input } from '@droppy/design-system'
```

<Canvas of={InputStories.Default} />

## Features

- **Label, control, and error message are wired together automatically** — Field's `for`/`id` and `aria-describedby` association, so you never generate or pass an id yourself.
- **The error slot is always reserved**, whether or not a message is showing, so validating one field never shifts the fields below it.
- **Accepts every native `<input>` prop** (`type`, `placeholder`, `autoComplete`, and the rest), so email, tel, and plain text fields are all the same component.
- **No `aria-label` layered on top of the visible label.** Field's association already gives the input its accessible name, so what a screen reader announces always matches what's on screen.
- **`className` merges onto the underlying input**, so wrapping it in `styled()` or adding utility classes composes instead of replacing Droppy's own styling.

{/* END: general */}

## How it works

The error slot keeps its height whether or not a message is showing, so validating one field never
shifts the ones below it.

<Canvas of={InputStories.ErrorDoesNotShiftLayout} />

Base UI's `Field` wires the label, the control and the error together — `for`/`id` and
`aria-describedby` — so the caller never does it by hand. That is also why the component sets no
`aria-label` of its own: an `aria-label` on top of a real `<label>` overrides the visible text,
leaving what a screen reader announces disagreeing with what the page shows.

## Anatomy

A field root wrapping a label, the control, and an always-mounted error slot. The slot is the unusual part: it stays in the DOM holding a non-breaking space when there is no message, which is what reserves the height.

<Canvas of={InputStories.Anatomy} />

| Part    | `data-part` | Renders   | Purpose                                                          |
| :------ | :---------- | :-------- | :--------------------------------------------------------------- |
| Root    | `root`      | `<div>`   | Base UI's `Field.Root`, wiring label, control and error together |
| Label   | `label`     | `<label>` | Absent when `label` is empty                                     |
| Control | `control`   | `<input>` | The control itself; `className` lands here                       |
| Error   | `error`     | `<div>`   | Always mounted, so showing a message never moves the layout      |
