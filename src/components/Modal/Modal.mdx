# Modal

A centered overlay that asks for one decision before the page continues.

- **Import:** `import { Modal } from '@droppy/design-system'`
- **Built on:** Base UI [`Dialog`](https://base-ui.com/react/components/dialog).

## Features

- **Focus trap** — Tab loops inside the popup while it's open, so keyboard users can't tab into the page behind it.
- **Scroll lock** — the page behind the modal stops scrolling while it's open.
- **Escape and outside-press dismissal** — closing doesn't need a pointer to hit the close button exactly.
- **Bottom sheet on mobile** — below 768px the popup docks to the bottom edge and slides up instead of appearing centered.
- **Portal by default** — content renders at the end of `document.body`, so a parent's `overflow: hidden` or `z-index` stacking context can't clip or bury it.
- **ARIA dialog wiring** — `role="dialog"` and the accessible name are set for you.

## When to use

- A single decision that should block the rest of the page until it's made — the `Open` story's "Remove from cart?" confirmation is the shape: state the consequence, offer a way out.
- A short, self-contained task that doesn't need its own page or route — collecting one field before an action runs, as in the README's `Input` + `Button` example.

## When not to use

- To show content the person reviews _alongside_ the page rather than instead of it — a cart, a filter panel, anything they might dip in and out of — use [Sidebar](?path=/docs/components-sidebar--docs). Modal takes over the page; Sidebar shares it.
- To explain what a control does before it's activated, use [Tooltip](?path=/docs/components-tooltip--docs) — a hint doesn't need a decision or a focus trap.

## How it works

### Open and close

`Modal` is controlled: `isOpen` decides whether it's rendered, and `onClose` fires whenever Base UI's `Dialog` decides it should close — clicking the close button, pressing Escape, or clicking the backdrop. There's no uncontrolled mode; the caller always owns `isOpen`.

<Canvas of={ModalStories.OpensAndCloses} />

### Dismissal

Escape closes the modal from anywhere inside it, and clicking the backdrop closes it without needing to find the close button.

<Canvas of={ModalStories.EscapeDismisses} />

### Focus behavior

On open, focus moves to the popup itself rather than the close button — landing on "close" the instant a modal opens reads as an invitation to leave before the content's been seen. Tab still reaches the close button first from there, and it stays reachable by keyboard throughout.

### Portaling

`container` decides where the modal is portaled: pass an element, a CSS selector string, or leave it unset to default to `document.body`. A selector is resolved after mount, so on first paint the modal portals nowhere — the correct order, since it starts closed anyway.

### Responsive behavior

Below 768px, `Modal` renders as a bottom sheet: full width, docked to the bottom edge, rounded on its top corners only, sliding up from the bottom on open. At 768px and above it becomes a fixed-size card, centered on the screen, fading and scaling in instead of sliding — there's no screen edge for it to slide from.

## Keyboard & screen reader

| Key                 | Action                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Tab` / `Shift+Tab` | Moves focus through the popup's tabbable elements; loops back to the start rather than escaping to the page |
| `Escape`            | Closes the modal                                                                                            |

- **ARIA**: the popup carries `role="dialog"`; the accessible name comes from the `aria-label` prop (default: `"dialog"`).
- **Screen reader**: on open, the dialog is announced using its accessible name; on close, focus returns to wherever it was before the modal opened.
- **You must provide:** a meaningful `aria-label` — the default value is a placeholder, not a real description of the decision being asked. Content inside the modal should also be reachable by Tab; nothing else is required to make it focusable, since the popup itself receives initial focus.

## Styling

- `className` — merged with the modal's own classes, so wrapping `Modal` in `styled()` or adding utility classes composes rather than replacing the built-in styling.

Modal has no CSS custom properties of its own to override — its dimensions and breakpoint are fixed by the design system. Use `className` for one-off layout changes.

## Decision log

- **2020-10**: overlays must lock body scroll while open — established as an early Mealdrop fix long before the design system existed, later delegated to Base UI's built-in scroll lock when Modal moved to Dialog ([mealdrop #2](https://github.com/yannbf/mealdrop/pull/2), [scroll-lock commit](https://github.com/yannbf/mealdrop/commit/c4aef0406a2e1cfddb072c9718d9f64f3c1fefdf)).
- **2025-01**: Droppy's Modal wraps Base UI Dialog and inherits its argued upstream contract: Portal is an explicit required part, keyboard focus is trapped regardless of modality, outside-press closes a dialog only via its own backdrop so sibling modals can coexist, and aria-modal is deliberately avoided in favour of aria-hiding outside content with a live-region exception so toasts still announce ([Dialog research brief](https://github.com/storybook-tmp/base-ui/blob/research/research/c-components/dialog/brief.md)).
- **2026-07**: Modal moved to Base UI Dialog.Root/Portal/Backdrop/Popup, retiring the hand-rolled Portal component, CSSTransition animations, Escape hook, and body-scroll lock in favour of Base UI's focus trap, Escape handling, and scroll lock; the `#modal` portal target and test ids were preserved so existing play tests kept passing ([modal commit](https://github.com/yannbf/mealdrop/commit/8e76d7061086ee7f9cb809e28cc5083b0dcf6d55), [mealdrop #62](https://github.com/yannbf/mealdrop/pull/62), [migration commit](https://github.com/yannbf/mealdrop/commit/dea29009cb06ec78eb7e2c52f216da78d913e747)).
- **2026-07**: Modal took a `container` prop accepting an element or CSS selector (default document.body) because Mealdrop portalled into a `#modal` node hard-coded in its own index.html and a package cannot assume that node exists; selector resolution happens in an effect, safe because an overlay is closed on first paint anyway ([Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md), [useContainer.ts](https://github.com/yannbf/droppy-ds/blob/main/src/utils/useContainer.ts), [mealdrop #63](https://github.com/yannbf/mealdrop/pull/63)).
- **2026-07**: the pixel-parity pass separated theme opinion from structural behaviour: the theme's DialogPopup defaults (padding, flex gap, negative margin, border) were reset for edge-to-edge modal content, the backdrop darkened from the theme's 20% scrim to the original 40%, and the 120ms fade+scale desktop open restored over the theme's 300ms — establishing motion tokens as brand voice a consumer may legitimately retime ([popup padding commit](https://github.com/yannbf/mealdrop/commit/eee6cb87fefbef385265776839ba512cb04f5807), [scrim/spacing parity](https://github.com/yannbf/mealdrop/commit/e085f7d327906cc5568613e3fab91e343cd5ef6f), [animation timing](https://github.com/yannbf/mealdrop/commit/ac151a9710b9eb297274485d7bfa571f7acf19aa)).
- **2026-07**: on open, focus goes to the popup container (tabindex −1) via initialFocus instead of the close button, so the modal opens without a visible focus ring while keyboard users can still Tab to the close button; popup overflow was restored to visible so a fixed-height card doesn't grow a scrollbar for its last few pixels ([initialFocus commit](https://github.com/yannbf/mealdrop/commit/7fd8d393288a13daff0295aa392f02e3f2acf94f)).

## Known issues & open questions

- [#217](https://github.com/yannbf/droppy-ds/issues/217): content taller than the fixed frame (272px desktop, 50vh mobile) spills outside the popup with no way to scroll (open; has workaround: give your content wrapper its own max-height and overflow: auto, or re-assert `max-height`/`overflow: auto` on the popup via the `className` prop from app CSS).
- [#218](https://github.com/yannbf/droppy-ds/issues/218): onClose carries no reason or event — dismissal sources are indistinguishable and cannot be selectively blocked (open; partial workaround: ignore `onClose` (don't flip `isOpen`) to veto every close path at once; per-reason control requires composing Base UI's Dialog directly).
- [#219](https://github.com/yannbf/droppy-ds/issues/219): accessible name is a flat aria-label defaulting to "dialog" — the visible title cannot be associated with the dialog (open; partial workaround: always pass an `aria-label` mirroring the visible heading (share one constant) and enforce it via an app-level wrapper with a required prop; id-based association is not achievable).
- [#220](https://github.com/yannbf/droppy-ds/issues/220): two open Modals break pointer isolation: the rear modal stays clickable while aria-hidden, and a nested Modal renders no backdrop (open; has workaround: avoid two simultaneous Modals, or portal the top one via `container` into a host element stacked above z-index 99; dim nested cases via `[data-nested-dialog-open]` app CSS).
- [#221](https://github.com/yannbf/droppy-ds/issues/221): close button's accessible name is hardcoded English "close modal" with no way to localize it (open; has workaround: hide `.droppy-Modal-topBar` with app CSS and render your own localized close button inside children (Escape/backdrop dismissal still work)).
- [#222](https://github.com/yannbf/droppy-ds/issues/222): open/close animations ignore prefers-reduced-motion — a full-height 300ms slide plays for reduced-motion users (open; has workaround: an app-level `@media (prefers-reduced-motion: reduce)` rule setting `transition: none` on `.droppy-Modal` and `.droppy-Modal-backdrop`).
- [#223](https://github.com/yannbf/droppy-ds/issues/223): invalid or empty `container` selector string crashes the app on mount, even while the modal is closed (open; has workaround: resolve the element yourself (try/catch around querySelector, or a callback ref) and pass an HTMLElement — never an unvalidated selector string).
- [#224](https://github.com/yannbf/droppy-ds/issues/224): positioned child content paints over the close button, leaving it visible but unclickable (open; has workaround: one line of app CSS, `.droppy-Modal-topBar { z-index: 1 }`).
- [#225](https://github.com/yannbf/droppy-ds/issues/225): `container` selector resolves once after first paint: an open modal re-parents (remounting its contents), a non-matching selector silently falls back to document.body, and the docs' "portals nowhere" claim is wrong (open; has workaround: pass a stable HTMLElement held in state via a callback ref instead of a selector or `ref.current`, and avoid changing `container` while open).
- [#226](https://github.com/yannbf/droppy-ds/issues/226): backdrop fade is cut short on desktop close and entirely absent in dark mode (open; has workaround: app CSS aligning the desktop backdrop transition to 120ms and re-asserting the dark-mode fade rules at higher specificity).
