# Spinner

## Anatomy

The announcing wrapper, a decorative graphic, and the shapes the keyframes drive. Only the root reaches the accessibility tree.

<Canvas of={SpinnerStories.Anatomy} />

| Part    | `data-part` | Renders        | Purpose                                                  |
| :------ | :---------- | :------------- | :------------------------------------------------------- |
| Root    | `root`      | `<div>`        | The `role="status"` wrapper carrying the accessible name |
| Graphic | `graphic`   | `<svg>`        | The `aria-hidden` drawing surface                        |
| Dot     | `dot`       | `<circle>` × 3 | Same keyframes, staggered by negative `animation-delay`  |
| Arc     | `arc`       | `<path>` × 3   | The sweeping wedges behind the dots                      |

## Do's and don'ts

### Do

- Name what we're waiting for in `label`, e.g. "Loading your order" rather than a generic "Loading". The
  graphic is `aria-hidden`, so `label` is the only thing a screen reader gets.
- Show one spinner per wait, at the root level of all UI elements that are blocked; using multiple spinners
  would cause spam in screen readers

### Don't

- Never repaint `Spinner`: [brand guidelines](?path=/docs/brand-guidelines--docs) mandate
  that the spinner must use the brand color
- Don't wrap `Spinner` in your own `role="status"` region: the root already is one, so a wait
  would get announced twice if you wrapped it.
