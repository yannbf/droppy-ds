## Anatomy

The announcing wrapper, a decorative graphic, and the shapes the keyframes drive. Only the root reaches the accessibility tree.

<Canvas of={SpinnerStories.Anatomy} />

| Part    | `data-part` | Renders        | Purpose                                                  |
| :------ | :---------- | :------------- | :------------------------------------------------------- |
| Root    | `root`      | `<div>`        | The `role="status"` wrapper carrying the accessible name |
| Graphic | `graphic`   | `<svg>`        | The `aria-hidden` drawing surface                        |
| Dot     | `dot`       | `<circle>` × 3 | Same keyframes, staggered by negative `animation-delay`  |
| Arc     | `arc`       | `<path>` × 3   | The sweeping wedges behind the dots                      |

## Keyboard & screen reader

`Spinner` is non-interactive and has no keyboard behavior of its own.

- **ARIA:** `role="status"` on the root — an implicit polite live region, so assistive tech is
  notified without interrupting whatever the user is doing. `aria-label` carries the name, since
  `status` doesn't compute one from its content.
- **Screen reader:** announces `label` once, when the spinner mounts.
- **You must provide:** a `label` that says what's loading, when the default `"Loading"` isn't
  specific enough for the surrounding context — `"Loading your order"` next to a checkout button,
  for instance.
