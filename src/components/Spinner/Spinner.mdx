## Anatomy

The announcing wrapper, a decorative graphic, and the shapes the keyframes drive. Only the root reaches the accessibility tree.

<Canvas of={SpinnerStories.Anatomy} />

| Part    | `data-part` | Renders        | Purpose                                                  |
| :------ | :---------- | :------------- | :------------------------------------------------------- |
| Root    | `root`      | `<div>`        | The `role="status"` wrapper carrying the accessible name |
| Graphic | `graphic`   | `<svg>`        | The `aria-hidden` drawing surface                        |
| Dot     | `dot`       | `<circle>` × 3 | Same keyframes, staggered by negative `animation-delay`  |
| Arc     | `arc`       | `<path>` × 3   | The sweeping wedges behind the dots                      |

## Decision log

- **2026-07**: the brand teal ramp was promoted into the palette so the identity colour couldn't get lost again — Mealdrop hardcoded it in Logo.tsx/Spinner.tsx where its theme never saw it — under the [brand guidelines](?path=/docs/brand-guidelines--docs) teal rule — the identity colour is "reserved for brand surfaces: the logo, the loading spinner", never buttons, links, or interface chrome; the spinner shifts to the lime `brand-dark` ramp in dark mode.
- **2026-07**: Spinner got a real accessible name — `role="status"` with an aria-label from its `label` prop — replacing Mealdrop's off-canvas SVG `<text>` that nothing announced; the spin is CSS keyframes so prefers-reduced-motion slows the rotation to stay perceivable without strobing, rather than freezing it ([Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).
- **2026-08**: a visual-parity audit found the CSS port had carried the dot/arc motion but dropped the source SVG's SMIL opacity animation, and proposed restoring the mount fade as an opacity-only keyframe (safe to keep at full speed under `prefers-reduced-motion`). The PR was closed unmerged, so the spinner still pops in at full opacity and it is tracked as [#15](https://github.com/yannbf/droppy-ds/issues/15) ([droppy-ds #8](https://github.com/yannbf/droppy-ds/pull/8)).
- **2026-08**: the base arc's SVG `transform="rotate(90 50 50)"` presentation attribute was replaced by a CSS rotation class, so all three arcs now rotate through the same mechanism — the attribute had compounded with the shared `transform-origin: 50px 50px`, doubling the rotation and pushing the base arc outside the viewBox ([droppy-ds #289](https://github.com/yannbf/droppy-ds/pull/289), closing [#263](https://github.com/yannbf/droppy-ds/issues/263)).
- **Built on a plain `<div>` wrapping an inline `<svg>` — no Base UI primitive.** Droppy supplies the props, the theme classes, and the copy around it.

## Known issues & open questions

- [#179](https://github.com/yannbf/droppy-ds/issues/179): role="status" region has no text content, so the documented "announces label on mount" behaviour is not delivered. **Workaround:** keep your own permanently-mounted visually-hidden live region and write status text into it, treating Spinner as the visual half only.
- [#183](https://github.com/yannbf/droppy-ds/issues/183): graphic is below the 3:1 non-text contrast minimum in the default light theme. **Workaround:** override the `.droppy-Spinner-dot` / `.droppy-Spinner-arc` fills (or the two brand tokens) with darker values for light mode, or pair the spinner with visible loading text.
- [#187](https://github.com/yannbf/droppy-ds/issues/187): the hidden attribute has no effect — display: inline-flex on .droppy-Spinner overrides the UA [hidden] rule. **Workaround:** conditionally render instead of using `hidden`, or add `.droppy-Spinner[hidden] { display: none }` to app CSS.
- [#189](https://github.com/yannbf/droppy-ds/issues/189): graphic is fixed at 100x100px with no size prop, and className targets the wrapper rather than the SVG. **Workaround:** override the internal `.droppy-Spinner-graphic` class in app CSS, scoped through your own className.
- [#15](https://github.com/yannbf/droppy-ds/issues/15): spinner lost its mount fade-in. **Workaround:** add a one-shot opacity keyframe on `.droppy-Spinner` in app CSS.
- [#192](https://github.com/yannbf/droppy-ds/issues/192): prefers-reduced-motion rescales animation-duration but not the dots' negative delays, so the three dots bunch together. **Workaround:** rescale the delays to -1.6s / -3.2s inside a `prefers-reduced-motion` block in app CSS.
- [#195](https://github.com/yannbf/droppy-ds/issues/195): ref is accepted by SpinnerProps but never attached on React 18, which is inside the supported peer range. **Workaround:** on React 18, attach the ref to a wrapper element you own; the passthrough already works on React 19.
- [#197](https://github.com/yannbf/droppy-ds/issues/197): children are silently discarded and dangerouslySetInnerHTML throws, though both are accepted by SpinnerProps. **Workaround:** pass neither prop — render caption text as a sibling, and your own element for custom artwork.
- [#199](https://github.com/yannbf/droppy-ds/issues/199): root is a hard-coded &lt;div&gt; with no polymorphic escape hatch, so inline placements produce invalid nesting. **Workaround:** keep Spinner out of `<p>`/`<button>`/`<label>` — render it as a sibling, and pass `aria-hidden` if it must sit inside a button.
- [#202](https://github.com/yannbf/droppy-ds/issues/202): a passthrough aria-label silently overrides the label prop, and role="status" can be replaced the same way. **Workaround:** set the accessible name only through `label` and never pass `aria-label` or `role` to Spinner.
- [#203](https://github.com/yannbf/droppy-ds/issues/203): AnnouncesLoading story description says a visually-hidden label carries the accessible name, which the component does not render. **Workaround:** ignore the story description and follow the MDX "The accessible name" section, which is accurate.
