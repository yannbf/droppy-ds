# PageTemplate

The page shell: header, a `<main>` content area, and footer — the top-level layout every routed
page sits inside.

- **Import:** `import { PageTemplate } from '@droppy/design-system'`
- **Built on:** a plain `<div>` wrapping a `<main>` element.

<Canvas of={PageTemplateStories.Default} />

## Features

- `header` and `footer` are optional slots rendered outside the `<main>` landmark, above and below
  the content area respectively.
- `children` renders inside `<main>` — the one content landmark per page, so assistive tech can
  jump straight to it.
- The content area carries `min-height: calc(100vh - 200px)`, a literal allowance for a typical
  header + footer height, so a short page's footer still lands at the bottom of the viewport
  instead of riding up under the fold.
- Merges any incoming `className` with its own `droppy-PageTemplate` class.

## When to use

- As the outermost layout of a routed page, wrapping the app's own header and footer components
  around whatever page content renders for that route.

## When not to use

- For a section within a page — use [Container](?path=/docs/layout-structure-container--docs) or
  [PageSection](?path=/docs/layout-structure-pagesection--docs) instead.

## How it works

### Content only

`header` and `footer` are both optional — omit them for a bare content shell.

<Canvas of={PageTemplateStories.ContentOnly} />

## Keyboard & screen reader

`PageTemplate` renders no interactive elements of its own.

- **ARIA:** the content slot is a real `<main>` landmark.
- **Screen reader:** a screen reader's landmark navigation can jump straight to the main content,
  skipping the header.
- **You must provide:** the header and footer content, and any skip-link the app wants ahead of
  `<main>` — `PageTemplate` doesn't add one itself.

## Styling

| Token / value             | Used for                           |
| ------------------------- | ---------------------------------- |
| `100vh - 200px` (literal) | Minimum height of the content area |

No color or spacing tokens apply directly — `PageTemplate` is a layout shell; header, footer, and
content styling come from whatever is passed into its slots. `className` merges with the
component's own `droppy-PageTemplate` class.

## Decision log

- **2020-09**: Mealdrop's page template shipped as a Header+Container+Footer wrapper and split within days into three variant exports — default, sticky header, and logo-only — establishing that page chrome varies per page; the content area's `min-height: calc(100vh - 200px)` literal dates from the same weeks and survives in Droppy unchanged ([template created](https://github.com/yannbf/mealdrop/commit/1e1550f8974e6381520d56380159b6edca8205cc), [three templates](https://github.com/yannbf/mealdrop/commit/9de500f658f392616db4b1dc513b988163a88a3e), [min-height](https://github.com/yannbf/mealdrop/commit/372790b024ed199af508ec435fbdd838fdcd251c)).
- **2021**: the logo-only template dropped its footer — not every page wants one — and the three exports later merged back into a single `PageTemplate` switched by a `type` prop, the direct ancestor of Droppy's one-component API ([footer removed](https://github.com/yannbf/mealdrop/commit/db8312485efa8f7d79131aa835377a40d2a1dbe1), [templates merged](https://github.com/yannbf/mealdrop/commit/d73285877d84155f506da777aa7cb9e11c5ef969)).
- **2026-08**: Droppy rebuilt the template as a pure slot shell: the closed `type` enum and the baked-in app Header/Footer went away in favour of opaque `header`/`footer` ReactNode slots — the parity doc excludes Header as "routing, cart state and a logo — an application component" — and a real `<main>` landmark replaced Mealdrop's plain div; the 2020 min-height literal was kept, documented in the stylesheet as an offset no token models ([initial commit](https://github.com/yannbf/droppy-ds/commit/00b19b5a1be01ae266251a71bd074e28ad8cd267), [Mealdrop parity doc](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)).

## Known issues & open questions

- [#269](https://github.com/yannbf/droppy-ds/issues/269): nesting one `PageTemplate` inside another renders two `<main>` landmarks in one document — nothing guards against it. **Workaround:** render a single `PageTemplate` per page, at the app-layout level; inner sections should be plain elements.
- [#270](https://github.com/yannbf/droppy-ds/issues/270): the content area's `min-height: calc(100vh - 200px)` assumes ~200px of combined header/footer chrome — taller slots break the footer-at-the-bottom promise, shorter ones force empty scroll space. **Workaround:** override `min-height` on `.droppy-PageTemplate-content` in app CSS when your chrome differs substantially.
- [#125](https://github.com/yannbf/droppy-ds/issues/125): the prop type is a closed set, so `id`/`data-testid`/`aria-*`/`style`/event handlers never reach the rendered DOM.
