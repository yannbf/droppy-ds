# Getting started

`@droppy/design-system` is the Droppy design language as React components. Base UI supplies
the behaviour — focus management, dismissal, positioning, ARIA wiring. This package ships its
own theme — the design tokens and the chrome — plus a component layer on top: components with
props instead of class names, so consuming code says `<Button clear round icon="cross" />`
rather than binding theme classes at every call site.

## Install

Every commit publishes a build through [pkg.pr.new](https://pkg.pr.new). Take the SHA from the
commit you want:

```bash
npm install "@droppy/design-system@https://pkg.pr.new/yannbf/droppy-ds/@droppy/design-system@<sha>"
```

`@base-ui/react` and `react` are peer dependencies — install them alongside.

## Import the stylesheet

Once, in your app entry:

```tsx
import '@droppy/design-system/styles.css'
```

It carries the Droppy tokens and every component's styles. Then import components anywhere:

```tsx
import { Button, Input, Modal } from '@droppy/design-system'

export const RemoveItem = ({ isOpen, onClose }) => (
  <Modal isOpen={isOpen} onClose={onClose}>
    <Input label="Reason" />
    <Button large>Remove</Button>
  </Modal>
)
```

Every component merges an incoming `className` rather than replacing its own, so wrapping one
in `styled()` or adding utility classes composes instead of stripping the design system's
styling. The cascade is ordered: theme rules first, component rules second, and anything the
app writes last — app CSS wins at equal specificity without `!important`.

## Theming

Droppy flips light and dark by a `data-ds-theme` attribute on the root element. Unset, the tokens
follow the OS `prefers-color-scheme`:

```tsx
document.documentElement.dataset.theme = isDark ? 'dark' : 'light'
```

`IconButton` is the one component that doesn't respond to the theme — it stays a light pill in
dark mode because it's built for floating over photography, not over a themed surface.

## Tokens in JS

Every design token is also available as data, for app code that styles outside the
stylesheet — a styled-components theme, a canvas, color math:

```ts
import { tokens, cssVar } from '@droppy/design-system/tokens'

cssVar('color.text.primary') // 'var(--ds-color-text-primary)' — follows the active theme
tokens['color.text.primary'] // { css: '--ds-color-text-primary', light: '#2c2c2c', dark: '#fff' }
```

Prefer `cssVar()` wherever a CSS variable can go — it stays correct when the theme flips.
The `light`/`dark` literals are fully resolved and always match what the stylesheet renders;
`dark` is present only where the themes differ.

## Portaling

`Modal` and `Sidebar` render into a portal and accept a `container` prop — an element or a CSS
selector — instead of assuming a fixed portal node exists in the page. It defaults to
`document.body`. Pass a selector to portal into an app-specific node instead:

```tsx
<Modal container="#modal" isOpen={isOpen} onClose={onClose}>
  ...
</Modal>
```

See [`docs/MEALDROP-PARITY.md`](https://github.com/yannbf/droppy-ds/blob/main/docs/MEALDROP-PARITY.md)
in the repository for the full list of behaviour and appearance differences from the
components these were migrated from.

- [Select](?path=/docs/forms-input-select--docs) — a single choice from a short, known list
- [Modal](?path=/docs/overlays-modal--docs) — a decision that blocks the page
- [Sidebar](?path=/docs/overlays-sidebar--docs) — a panel reviewed alongside the page, carts, filters
- [Tooltip](?path=/docs/overlays-tooltip--docs) — a hint for a control whose face doesn't explain it
- [Container](?path=/docs/layout-structure-container--docs) — a max-width page wrapper with responsive padding

- [ProgressBar](?path=/docs/feedback-status-progressbar--docs) — a track-and-fill indicator for a known number of steps
- [Breadcrumb](?path=/docs/navigation-breadcrumb--docs) — a trail of ancestor pages above the current one
- [QuantityStepper](?path=/docs/forms-input-quantitystepper--docs) — a minus/plus pair for adjusting an item's count
